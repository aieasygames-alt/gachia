## 修复的真实阻塞

批量测试首次失败于 `Structured Content` 字段校验。统一模型支持 TypeScript 字符串区块，但 Payload 默认 JSON 校验器将字符串值当成序列化 JSON 再解析；草稿导入可以成功，审核为 published 时失败。

已仅对 `structuredValue` 改为实际 JSON 值校验。来源身份、原类型/结构、危险文本、审核权限、hold 和正式版本隔离仍由原有集合合同执行，没有放宽正式发布范围。

失败证据：`payload-batch-tests.log`。修复后首轮：`payload-batch-tests-fixed.log`，真实 Payload 隔离库中的全部 16 scope、139 行类型完成草稿、审核、正式版本读取与批量候选导出，10/10 测试通过。候选值经 JSON/TypeScript reader 重读一致；不是线上构建或消费者验收。

最终完整 CMS 回归：**384/384，0 失败、0 跳过**，耗时约 351 秒；内部固定适配器 119 项通过，见 `cms-tests.log`。字段及覆盖/生产范围的聚焦验证通过，最终矩阵调整另跑覆盖测试 **3/3**，见 `coverage-tests.log`；`pnpm typecheck` 通过，见 `typecheck.log`。没有执行本轮精确提交的远程 CI。

批量回归实际覆盖的字符串区块为绿梦 `patchSource`、`launchSource`、`rewardsSource`，终末地 `END_FIELD_TIER_SNAPSHOT_UPDATED_AT`，归环与绝区零 `updatedAt`。所有这些区块都经真实审核和正式读取后进入候选，并非仅测试校验函数。

4. 单独补 20 个结构型单元及其他实体新增、撤回、媒体和页面内联内容。

本轮没有修改常驻数据库、安装 CMS 新版本、构建发布产物、云端上传或切流；没有删除备份、历史证据或游戏内容。
