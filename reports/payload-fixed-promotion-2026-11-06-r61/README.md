# R61 私有推广函数与来源接续组合

## 实现

- 修复私有 `promoteUnifiedMain` 的异步输入问题：入口固定请求、CMS/云令牌和 release key；收据引用已经打开的请求，避免操作中途读取调用方修改后的值。
- 固定组合现在通过仅限测试的导出 hook 执行真实私有推广函数，再将其生成的收据交给真实完成态 reader、来源接续及来源 reader。此前该组合的推广收据来自协议级 fixture。
- 新增六项组合用例：成功、调用方异步修改输入、错误授权、预览失败、部署响应丢失、公网验收失败。成功后完整消费 115 来源；失败不得生成成功收据；未知结果不重试，已有推广日志拒绝再次执行，网络资源正确关闭。
- 保留 fixture 初始合成日志为 `.fixture-seed`，新尝试写自己的日志；只操作临时测试目录。共享 fixture 的 network pin 新增可选输入，默认行为保持。

## 边界

这是合成网络响应下的固定组合，不是实际云推广。本组推广用例额外替换了 live CMS 生产预检，历史发布根仍是隔离返回；没有放宽生产函数、资格检查或请求语法。历史预览、模块、续验、云拓扑、推广协议、部署响应、完成态和来源接续 reader 使用真实实现。

CLI 的推广/恢复 writer 仍私有。本轮没有安装 CMS、上传新版本、切换公网、创建真实完成态或进行实际来源接续；也没有本轮精确提交 CI。R60 对真实历史根的本机验证仍与本组合分开，不能把两者相加宣称无替换的完整生产资格。

下一步是补齐包含真实生产预检和历史根的完整请求链，再完成当前执行器精确 CI、新鲜续验、正式推广、公网接受与实际来源接续。首个 Main-only 真实闭环尚未完成，其余游戏不提前宣布可正式更新。
