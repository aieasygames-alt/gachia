# 星穹铁道线上内容审计 · 2026-11-25

当前最需要处理的是资料可信度、工具可用性，以及新版内容与旧入口之间的断层。版本页的14条CMS内容已更新到4.7，主站首页、角色数据库、攻略和工具仍各自读取旧数据。继续增加版本页条目，不能自动补齐这些栏目。

本轮为只读审计，没有修改线上内容、CMS记录或部署。

## 检查范围与证据

全量抓取875条sitemap URL，补查12条导航入口和35条正文链接，共922个请求URL，重定向后覆盖915个不同页面：中文、英文、日文各305页。中文对应17个入口/工具页、81个角色页、85个光锥页、62个材料页、32个遗器页和28个攻略页。所有请求最终均返回200；其中活动日历是空内容，工具交互仍能触发错误，不能用HTTP成功率代表内容质量。

人工重点复核首页、版本页、卡池规划、欢愉/记忆机制、终局、刷取、装备、兑换码、地图与下载内容。浏览器实测首页、活动日历、材料计算器、配装、角色对比、节奏榜，避免把服务端的Loading占位误报成页面故障。节奏榜初始0/0随后正常加载为81/81，**不属于空榜故障**。

本次没有逐项独立核验全部角色倍率、全部光锥叠影效果或实际提交兑换码，也没有使用Search Console、流量或排名数据。优先级依据可复现错误、内部矛盾、玩家资源决策影响和当前版本相关性。

- `summary.json`：范围和统计；`page-index.json`、`linked-page-index.json`：逐URL状态、标题、描述、标题层级与摘要。
- `evidence.json`：重点页面原文证据；`browser-observations.json`：浏览器复现步骤和结果。
- `data-gaps.json`：占位角色、缺材料角色、配装结构不兼容角色、无更新日期攻略的完整ID清单。
- `.private/`：原始抓取及抽取全文，已忽略；`crawl.py`可重现只读抓取。

## P0：先修可复现故障及会误导决策的内容

### 1. 配装和角色对比会因部分角色数据不完整而崩溃

- [配装页](https://gachia.com/zh/starrail/build)：选择银狼LV.999后出现“Something went wrong”。控制台报`Cannot read properties of undefined (reading 'toLowerCase')`。
- [对比页](https://gachia.com/zh/starrail/compare)：A选择银狼LV.999，B选择希儿，同样进入错误页。
- 源码中的配装和对比解析直接调用`build.bestLightConeEn.toLowerCase()`；源数据有30个角色缺此字段。**已复现两个工作流，不等于逐个实测全部30个角色**。
- 建议：先对缺失推荐数据提供可见的“待补充”状态并保护解析；再补资料，不应靠编造推荐项消除报错。验收需覆盖完整与不完整角色的选择、切换和对比。

### 2. 角色身份错误与大量占位技能/星魂

- [Castorice角色页](https://gachia.com/zh/starrail/characters/castorice)标题、配队和FAQ都写“卡芙卡”，与`/characters/kafka`混为同名角色；列表及工具选择器也继承了这个错误。
- 在线81个角色中，**50页直接出现“星魂第1层效果”**，战技/终结技等正文为“释放战技，对敌方造成伤害或提供增益”“释放强大的终结技”等模板；这些不是有效技能资料。
- 另外31个角色没有星魂记录。以[爻光](https://gachia.com/zh/starrail/characters/yao-guang)、[火花](https://gachia.com/zh/starrail/characters/sparxie)为例，页面显示技能栏目但没有名称和说明；[银狼LV.999](https://gachia.com/zh/starrail/characters/silver-wolf-lv999)只显示一段普攻说明。
- 建议：第一批修身份与命途等基础字段，并明确显示缺失状态；优先补阿哈及当前/近期复刻角色的完整技能、星魂、行迹、培养目标和来源。其他角色逐批替换占位内容。

### 3. 终局规则互相矛盾

- [终局玩法攻略](https://gachia.com/zh/starrail/guides/endgame-modes-guide)FAQ说“每个终局模式有3个关卡，每关3星，共9星”。
- [三大终局攻略](https://gachia.com/zh/starrail/guides/endgame-cycle-guide)表格又把混沌、虚构、末日都写成“30星”；正文还写混沌“10个节点”，FAQ按每模式600星琼估算奖励。
- 两页对同一玩法的基础口径不能同时成立；当前关卡、星数、计分与奖励均应逐模式重新核准，禁止简单全局替换数字。
- 建议：区分“模式基础”与“当前轮次”，当前轮次引用CMS已核准的国服正式日程；敌人、增益、奖励和阵容各自核验。

### 4. 刷取攻略存在跨游戏规则与数量矛盾

- [素材刷取攻略](https://gachia.com/zh/starrail/guides/farming-route-guide)写历战余响“首次30，后续60开拓力”、材料用于“行迹10→12级”，还出现“光锥突破材料（幻想真境）”“庄严的宗室”等混杂表述。
- [Boss攻略](https://gachia.com/zh/starrail/guides/boss-strategy-guide)FAQ则写每次30开拓力；[阿哈新资料](https://gachia.com/zh/starrail/version)明确技能常规培养上限与星魂加级分别统计，11—12级不额外支付培养材料。
- 刷取页另有“每天50星琼购买60开拓力（前6次）”、后备开拓力效率/容量、花萼消耗、双倍活动燃料建议等具体规则，需整体重新取证，不能只修日期。
- 建议：先复核周本、花萼、凝滞虚影、侵蚀隧洞和位面饰品五类来源，并清除其他游戏的机制和材料；重写为按目标角色和个人缺口分配体力的步骤。

### 5. 位面饰品攻略与本站遗器数据库直接冲突

- [位面饰品攻略](https://gachia.com/zh/starrail/guides/planar-sphere-guide)将竞技场效果写成“暴击≥70%时再+12%攻击”。[对应套装页](https://gachia.com/zh/starrail/artifacts/rutilant-arena)写的是普攻/战技伤害提高20%。
- 同一攻略把龙骨全队暴伤写为8%，[套装页](https://gachia.com/zh/starrail/artifacts/broken-keel)为10%；套装名称也出现“旭日竞技场/繁星竞技场”“碎裂/折断”等不一致。
- 建议：按套装ID建立统一效果数据，文章引用同一条记录；效果、触发门槛、适配角色与刷取入口一起核验。

## P2：内容维护与国际化

1. **地图与刷取位置**：[地图页](https://gachia.com/zh/starrail/map)仅5个区域，与首页已开放新区域的介绍不一致；214锚点、28花萼、15历战余响等精确统计没有来源和核验日期，Boss列表与副本分类也有混杂。[区域攻略](https://gachia.com/zh/starrail/guides/planarcadia-guide)摘要把Amphoreus/Planarcadia和黄金裔故事混在一起。先核准区域与副本名称，再补二相乐园等当前内容，缺依据时不展示精确总数。
2. **下载平台与空间**：[下载页](https://gachia.com/zh/starrail/download)仍以4.6入坑路径说明；将“PlayStation / Xbox”合并标为可玩并提及Steam绑定，空间统一建议40GB以上。应逐平台/区服独立核对商店、互通及最新空间要求；这次审计没有确认所有平台支持状态，不能直接据此给出替换平台清单。
3. **旧Fate/4.4专题**：v4.4专题及Himeko Nova、Rin/Gilgamesh等页面已有“历史归档”提示，但首页仍优先推荐，页面还将读者导向4.6。先退出当前推荐位；各角色/日期/联动奖励断言逐条追溯来源，历史标签不能代替事实核验。可以保留有价值的历史URL，不应只改版本号继续作为当前攻略。
4. **旧角色配装攻略**：知更鸟攻略同一专锥混用`Night upon the Milky Way / Flowing Nightglow`，阮梅攻略把`Memories of the Past`写为“记忆的质料”，行迹/星魂/词条也需重核。五篇角色配装文章应与结构化角色、光锥和遗器逐项对齐。
5. **来源、日期与中文术语**：28篇中文攻略正文均没有外部文章来源链接，源数据18篇没有`updatedAt`。中文内容还出现谐乐、想象、圣遗物、命座及英文维护说明。先统一同谐、虚数、遗器、星魂等术语，再为每篇补适用范围、来源和实际核验日，不以批量刷新日期制造新鲜度。
6. **英日版本内容**：当前CMS已发布中文14条，英语和日语各0条；对应版本页有通用外壳而无当前更新记录。日文28篇攻略有英语回退，已设`noindex, follow`并从sitemap排除，这是既有保护措施。建议先翻译当前版本、日程和阿哈核心资料，再逐批完成日文；不应把英文回退页面视为已经完成日文化。
7. **新手与常青攻略**：快速入门、模拟宇宙、开拓力、遗器、BOSS等需要补当前版本入口，核准免费角色获取条件、模式奖励、后备体力与装备规则。优先清除具体错误，再补篇幅。

## CMS链路的实际边界

现有4320 Payload只有`game-updates`业务集合，虽然支持`character`类型，但它仍是更新条目，不等于结构化角色库。主站只有版本页和公开CMS API调用`loadStarRailUpdates/getStarRailPublication`；首页、活动、角色、光锥、材料、配装和计算器尚未消费这份发布副本。其余数据库和攻略仍读raw JSON及构建生成的客户端数据。

建议按以下顺序小步接入：

| 批次 | 交付范围 | 发布方式 | 最小验收 |
| --- | --- | --- | --- |
| A：可用性与误导入口 | 配装/对比空值保护；缺材料提示；身份错误；首页4.7入口；当前卡池表 | 必要代码发布一次；可复用资料继续从现有CMS读取 | 两个已复现崩溃流程通过；首页/版本/卡池一致；缺数据有说明 |
| B：当前版本闭环 | 阿哈独立角色页、当前专锥/遗器/材料、活动日历；先修终局与刷取关键错误 | 增加必要结构化模型和读端，然后走草稿→正式发布→同步 | 同一条材料/倍率在角色页、资料条目、计算器口径一致；活动按区服和时间分类 |
| C：规则与旧库清理 | 欢愉/记忆、终局、体力和装备攻略；逐批替换50页占位内容及31份缺材料 | 每批3—5个高优先条目，逐条来源核验 | 正文无通用占位；角色/光锥/遗器引用ID一致；有来源、日期、边界 |
| D：扩展覆盖 | 模式化配队与榜单、地图/平台资料、英语和日语 | CMS日常内容更新为主 | 按真实修订日期发布；翻译和区服互相独立 |

不要先把全部旧JSON原样搬入CMS再宣布完成更新；导入应保留“待核验”状态，只有通过核验的资料进入公众正式视图。对独立站长，优先把当前角色和近期节点做成一条可复用的数据链，再补全历史库。
