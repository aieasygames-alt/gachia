目标仍为“所有游戏所有内容均可正式更新”。本轮补第一阶段的连续更新链路，不把隔离通过写成已正式上线。

## 实现

- 固定 `unified:source advance` 请求只接受已完成发布的请求 pin 和当前执行器完整 CI。首先重新打开历史 O、115 来源、审核、冻结/构建/transport、原始五 owner、预览/推广/公网/模块回执及各精确 CI；没有完成推广不能生成有效来源索引。
- 五 owner 索引仅替换 Main 为实际已接受候选的封存模块与完整兼容静态并集。其他四站保持各自原始来源，不从历史原神/异环 catalog 取旧 Main。只复制 Main 一份，复用其余四站；不重新构建、上传、切流或修改数据库。
- 新 A 直接来自完整封存源码，包含公开 JSON、非公开代码及派生输入；90 份公开 JSON 必须同时匹配 Main 产物和已接受公网引用。新鲜七服务拓扑、五个不可变版本的前后读取及完整 Main 公网观察单独留档。
- `unified:source baseline` 消费完整来源索引，再取一组独立的新鲜观察，输出 115 来源的 `active.json`、五 owner `previous.json` 和 `source-handoff.json`。不重新从旧 Git 推导代码 A；历史索引可读但不能延长下一批交接时效。
- `unified:source prepare` 重开固定完成态 reader、索引及新鲜交接；要求下一批构建完整消费新 A，才从五 owner 索引精确选取本批构建目标的旧产物，交给原候选/恢复本地准备器。来源索引本身始终保留五 owner。新入口不扩大生产编辑资格。

所有来源入口仅创建本地证据，`cloudWrites:false`、`activationSupported:false`、`newPublicationAuthorized:false`。推广与固定恢复写组合仍未开放。
