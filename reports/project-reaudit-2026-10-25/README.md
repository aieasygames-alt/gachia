# 项目再次审计与剩余任务

2026-10-25。源码基线 `334de6e6945c228b65860e3709558871d4e551ff`。审计开始时存在已批准的 119 份浏览器记录删除、`.gitignore` 修改及未跟踪清理报告；这些变更保留，不把工作树描述为干净候选。

## 主要发现

### F1 / P1：常用发布入口仍可绕过已采用的完整发布流程

- `apps/game-genshin/package.json:9`、`apps/game-lvmeng/package.json:12` 的 `deploy` 直接重新构建并调用 OpenNext deploy；`apps/web/package.json:10` 也保留独立的直接生产入口。原神/绿梦这两条命令没有绑定已验收版本 UUID、旧资源 receipt 或独立推广门禁。
- `scripts/game-release.mjs:120` 对 NTE 只要求服务名确认和格式正确的 rollback UUID；旧资源 receipt 的强制要求仅针对 Azur。`scripts/game-release.mjs:133` 的干净源码门禁同样只覆盖 Azur。
- 本地调用实际门禁函数：NTE 的脏工作树、发生变化的 commit、全零合成 rollback UUID、缺少旧资源 receipt 均可通过这两项检查。未调用构建/上传/推广，更没有测试真实回退版本。
- 风险是维护者使用正常 `pnpm deploy` 入口时，能绕过最近几批操作脚本提供的干净来源、旧资产兼容、远端同制品验收等保护。需具备部署凭据才会产生生产影响，不是匿名访问者可远程调用的漏洞，也不表示此前发布已经损坏。
- 建议优先将直接生产入口 fail-closed 或统一到受控上传/验收/推广流程；所有 live owner 使用一致的来源与旧资源约束。增加“脏源码/缺 receipt/伪回退来源/未验收 UUID 必须拒绝”的测试，再处理跨进程并发与过期审批。

### F2 / P2：主站 URL 规范化会抛异常或重定向到自身

- `apps/web/middleware.ts:110` 直接解码未经验证的 pathname；`/zh/%` 与 `/zh/%E0%A4%A` 在实际中间件源码中抛出 `URIError`，没有受控 400/404 响应。
- `apps/web/middleware.ts:165` 将解码路径与编码路径直接比较。`/zh/%E4%BD%A0` 被转换成中文后调用 redirect，NextResponse 又重新编码为原地址，返回指向自身的 301。爬虫/访问者将遇到循环，而非正常的不存在页面处理。
- 本地复现使用真实 NextRequest/NextResponse，周边语言中间件和数据依赖隔离；未向生产发送异常路径，也未宣称已实测边缘平台最终状态码。
- 修复应统一编码后的比较方式并保证规范化幂等，对非法转义明确拒绝；增加非法 UTF-8、编码非 ASCII、双语言和既有 slug 修复回归。

### F3 / P2：地图瓦片使用 32 位哈希作为唯一缓存身份

- `apps/web/app/api/map/tile/route.ts:42` 仅使用 map ID 和 `hashUrl(url)` 定位 R2 对象，命中时不核对原 URL；`apps/web/app/api/map/tile/route.ts:105` 使用 32 位字符串哈希及绝对值，不能作为唯一内容身份。
- 两个满足白名单的合成 URL：`https://act-webstatic.hoyoverse.com/map_manage/20261025/Aa.png` 与同目录 `BB.png` 均得到 `map-tiles/2/4zj5jb`。
- 使用内存 R2 和合成上游响应调用真实 GET：第一个 MISS，第二个直接 HIT 并返回第一个内容，上游仅请求一次。说明允许不同 URL 错用同一图片缓存，且响应含一年 immutable 缓存策略。没有请求真实瓦片或写入云端 R2，不声称当前真实资源已经发生碰撞。
- 建议改为规范化 URL 的 SHA-256 或无损键，并使用新缓存命名空间避免旧弱哈希对象继续误命中；增加碰撞样例回归。修复不应顺带执行缓存清除或删除旧对象。

### F4 / P2：公开分享读取不检查有效期，并返回完整数据库行

- `apps/web/app/api/shared-builds/route.ts:65` 只按 ID 查询，不检查 schema 已有的 `expiresAt`；`apps/web/app/api/shared-builds/route.ts:76` 直接输出整行，并允许公共缓存。
- `apps/web/app/[lang]/[game]/shared/[id]/page.tsx:34` 的页面读取同样未检查有效期，非队伍数据分支还直接输出完整行 JSON。
- 账号开关只关闭创建功能，公开历史分享读取是明确保留的行为，不能用“账号已关闭”排除此路径。合成数据库行设置 2020 年过期时间，API 仍返回 200，包含内部 `userId` 和过期字段，并设置公共缓存。
- 未读取生产分享或用户数据，不知道线上是否存在此类过期行。若有到期记录，目前不能实现到期停止访问；公开响应也没有最小字段边界。
- 建议 API 与页面共用公开分享读取器：过滤到期记录、明确允许输出的字段，并使缓存有效期不超过剩余寿命。该修复不需要重启登录，也不涉及删除账号或历史数据。
