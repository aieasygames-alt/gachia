## 故障调查与本地复验

首次故障为手机访问 `/ja/roco/guides/global-player-discovery-codex-playbook` 等待 networkidle 超过 60 秒。旧诊断只记已失败的脚本/样式，没有超时瞬间仍未完成的请求，因此无法事后证明阻塞请求及具体网络边界。

增加未完成请求快照：按请求对象区分相同 URL，保留类型、导航、耗时及已收到的响应状态，完成/失败后移除。受管内容捕获异常时先保存快照再关闭上下文。没有修改 networkidle、60 秒期限、资源错误或业务断言。单元测试和真实本地浏览器悬挂响应夹具验证超时仍被拒绝且未完成请求可记录。夹具最初额外要求 Chromium 已发出 response 事件，但实际事件尚未发出；随后只断言可观测的未完成请求，不推断未知 HTTP 状态，失败记录保留。

本机直连完整复验在首个 HTTP 请求即 fetch failed，与原 CI 后段浏览器超时不是相同证据。使用显式本地代理完成后续复验；XML 工具新增严格的 `--proxy` 参数，只允许无凭据 loopback HTTP 代理，默认仍忽略环境代理，原目标域名/路径/重定向/大小/索引断言不变。此代理复验不能代表原 CI 网络路径。

新 CI ZIP 实际下载并校验摘要，安全恢复 4,117 个条目。原本地构建移至受保护目录保留，未删除。恢复的精确制品用于旧资源和 XML 期望，本地源码的 apps/packages/lock 与生产源码无差异。复验前后 staging/生产版本、路由、域名和绑定相同。
