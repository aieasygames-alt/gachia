## 旧模块来源与接口差异

首次读取 `/content/v2` 被 ETag 断言拒绝：该次响应对应上一批已上传、未推广的 `6c0b7274...`，并非当前承载的旧生产版本。其 ETag 与上一批候选元数据一致，证据见 `endpoint-behavior.json`。没有把这份错误版本脚本用于回退验证，也没有将此观测泛化为所有 Cloudflare 接口的保证。

旧生产模块使用上一批已保存的权威云端 multipart：先验证原 receipt 及 archive 摘要，再核对本次生产 UUID、deployment、版本 ETag 全部与原捕获一致，解析模块并核验已知摘要 `083f01784b2e5a817d65e0213a341f27700a15ad4c878dcd71d3bc1024e476cc`。旧静态资源则全部重新下载，并在捕获前后重新读取生产身份。

因此本批旧模块来源是“已保存的、与同一不可变版本对应的云端归档”，不是“本次重新下载的旧脚本”。Git 来源仍为历史操作关联而非平台签名证明；68 份资源清单也不宣称是 Cloudflare 全部历史资产目录。新版本推广后重新下载的云模块 ETag 与新生产版本一致，模块摘要与上传 multipart 相同。
