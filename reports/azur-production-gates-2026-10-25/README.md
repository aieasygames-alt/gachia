首次只读控制面查询遇到 OAuth 401，经 Wrangler 正常刷新会话后继续；没有记录凭证。之后两次 30 秒读取超时。最终一次只读诊断将脚本下载限时延长至 90 秒，约 594 ms 收到 HTTP 200 响应头、86,962 ms 完整收到 5,400,067 字节，并核验摘要成功。原始失败日志保留，没有用历史缓存替代本次读取，也不将观测到的慢下载归因为已证实的 Cloudflare 故障。

## 上传后门禁为何失败

原始配置包含 staging 环境定义，线上设置原有 `cf:service=gachia-game-azur-promilia` 分组标签。本轮封存工具先前照搬其他 owner 的处理，移除了 `env` 块，错误假设蓝色星原也应保留空服务标签。

Wrangler 4.148.0 的 `applyServiceAndEnvironmentTags` 根据解析后的 `definedEnvironments` 决定服务标签；`versions upload` 随后调用非版本化 `script-settings` 更新标签。即使只上传、尚未推广，也会产生这个控制面副作用。本次上传将标签从原值变为 `[]`，因此对账失败。上传成功和门禁失败的日志均保留，未重复上传。

处置分为两步：

1. 新一轮只读对账确认差异仅为已知标签和预期上传消息，且生产仍为旧版本；随后仅 PATCH `script-settings` 的 `tags` 字段恢复原值。最终再次对账，除预期上传消息外，其余设置及全部部署与上传前一致。
2. 修正本地 `liveOwnerConfig`：蓝色星原保留完整、逐字段白名单核验的环境定义，实际目标仍显式选择空环境和 production 模式，不改 staging 服务。增加使用已安装 Wrangler 的配置解析器及真实标签转换函数的回归测试，同时复现旧剥离配置会清除标签的行为。

标签恢复不是生产推广，也不是将失败门禁改成通过。没有执行版本删除、再次上传或自动回退。
