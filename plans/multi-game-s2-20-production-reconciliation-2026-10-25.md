## 本批实现

1. 保留全部严格浏览器断言，增补同源脚本/样式失败原因、HTTP 错误状态、页面与主文档导航关联；逐条落盘，断言失败时记录截图和页面地址。原 CI 未记录 failureReason，不能事后认定是网络抖动或导航取消。
2. 新增手动、仅 main、与 Main 发布共用互斥组的只读生产复验。没有构建、部署、回滚、路由写入或缓存清理命令；延用停用账号 API 的合成过期 Cookie/畸形请求体拒绝探针，以及未认证 IndexNow 401 探针。这些探针含 POST/PUT/DELETE，但均要求停用门禁先拒绝、无 Cookie 刷新，不写业务数据，不提交搜索引擎；并非声称所有公网请求都是 GET。
3. 对原始部署要求可信 main 手动运行、build/staging 成功、实际部署步骤成功、精确 artifact 与版本日志匹配；双重摘要验证并安全恢复同一封存产物，不重建旧代码。
4. 复验前后核对生产版本、七个 Worker 的部署/绑定、域名与路由；Main 必须仍是指定单版本 100%。执行完整 32 HTTP、18 runtime browser、520 managed browser、171 NTE HTTP、raw/search/旧静态抽样、严格 XML 图、全部静态字节及原 CI 未执行的 HI3 阅读探针。前后 XML owner 集合必须相等。
5. 仅复验全部通过才输出 receipt；独立 GitHub workflow/job 成功、精确 ZIP 摘要与 artifact ID、可信 main 来源、原产物/版本/源提交对应都满足时，下次发布才能显式接纳此回执。普通成功 deploy 来源路径保持原样，失败来源没有回执仍拒绝，生产写入前仍实时核对 active rollback UUID。
6. 原神旧 pre-cutover production-origin 入口首先明确失败并提示已退役，防止本地默认 false 被误作实际 Router 未切流。没有借此发布原神或改变生产开关。
