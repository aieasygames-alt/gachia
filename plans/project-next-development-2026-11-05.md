# Gachia / Payload 下一阶段开发计划

日期：2026-11-05。依据[全面审计](../reports/project-audit-2026-11-05/README.md)、[R39交付](../reports/payload-new-guide-launch-2026-11-05-r39/README.md)及[限定V1](payload-v1-completion-2026-11-03.md)。本文是待执行计划，**不是开发、安装或部署完成证明，也不是新的生产写入授权**。

## 1. 目标与边界

短期目标：保住现有可用的 CMS-first 内容维护，修复已确认安全缺口，在不破坏公开内容/缺译政策/恢复链的前提下接通 NTE 中文新增。

- 保留本机 Payload/PostgreSQL、公众 Cloudflare 多 Worker、CMS 独立依赖与锁文件；不重新选择云 CMS，不暴露 Mac，不加 Tunnel。
- 已关闭的 C01/C02/C03/C04/C05a 与原神正常新增不重做。原 P/T 全范围状态不因本计划关闭。
- 账号保持关闭、IndexNow保持显式暂停，账号删除仍取消；不把无关账号工作夹入 CMS 切片。
- 独立 key 按用户决定暂缓，不要求第二台 Mac；异地密文不等于整机灾备。
- 内容由代理规划后先写 CMS，再完整发布。准确度全量复查和补齐译文不变成技术上线前置，但不得捏造事实、版本数值或媒体权利。
- 不将“后台 published”“制品上传”“fixture通过”“精确CI成功”分别冒称公众发布。

## 3. 工作包与退出条件

### N01：先修输出，不先扩大内容输入

范围：原神/NTE已接入CMS的指南详情及相关JSON-LD测试；共用安全序列化策略，避免从游戏应用跨目录依赖Web私有模块。其他页面相同模式先建清单，按实际输入边界扩修，不顺便改版。

验收：

1. 真实消费者渲染的标题/摘要/FAQ含 `</script>`、混合大小写及特殊字符时，浏览器不产生额外DOM或可执行节点，JSON可解析且文本语义保持。
2. 普通标题、Unicode、多语言、metadata、canonical及结构化数据不退化；不把正文改成未经消毒的HTML。
3. 发布指纹采用与HTML语义一致的结构读取/拒绝规则，或明确增加独立安全DOM门禁；不能只让同一不安全输出在两端相等就通过。
4. 两owner候选/恢复兼容性及旧静态资源验收仍通过。公众修复实际上线与本机CMS安装分开记录；无CMS源变化不为凑验收改文章。

### N02：让当前分支验证当前消费者

范围：维护分支的验证型CI、有限运行文档入口和依赖适用性表。不在审计期间合并main，不开部署开关。

验收：

1. CI覆盖Web/Data/Router单测、受影响公众类型及N01消费者安全测试；无Cloudflare/生产数据库凭据。文档-only不重复完整双owner构建。
2. 对Better Auth 4个公告逐项记录版本、前提、当前配置、处置和复核条件；账号/插件重新启用前必须重新审查，不加无依据忽略名单。
3. 确认修复版本确已发布后才安排锁文件升级；deepmerge期限保持2026-11-16，不扩大当前loopback信任边界。
4. CMS README/项目地图当前入口与R39能力一致；旧批次保留为历史，UUID/生产来源始终新鲜取证，不靠文档硬编码授权。
5. 精确提交验证成功后才考虑受控合并。main基线、已公开A、CMS安装/publisher版本是不同身份，不能为合并而覆盖任一来源。

### N03：空间不足应在有副作用前拒绝

范围：prepare/build/本地恢复所需的轻量空间门禁和清理dry-run设计。不执行真实删除，不扫盘清缓存，不移动封存树。

验收：

1. 按同一文件系统检查剩余空间和任务临时预算；低于8GiB拒绝开始双owner构建，低于10GiB给出预警；阈值以上仍需满足估算余量。
2. 用注入的空间探针测试边界、读取失败和构建阶段变化；失败时不启动安装/子进程，不把prepared run提前标为building。
3. 清理候选必须理解当前/父source catalog、公开UUID、恢复run、pin和失败journal依赖；未知引用默认保护，输出每个候选的证据与影响。
4. dry-run不等于授权删除；实际目录级处置另行审阅。不可通过删key/旧恢复资源/失败证据满足阈值。

### N04：先形成统一NTE语言政策

范围：NTE guides列表/详情、读取helpers、metadata/JSON-LD、hreflang、game sitemap及发布验收；保留Main与NTE分割所有权，不误接管Main的items详情。

验收：

1. 对字段缺失、null、空串、空白、仅中文、仅英文、完整日文和部分日文建立同一矩阵；空串不可错误遮挡阅读回退。
2. 未译页面仍可按明确规则阅读原文，标识正确语言；缺合格译文时noindex且排除对应sitemap/hreflang，不复制中文伪装翻译。
3. 详情、列表、metadata、Article/FAQ JSON-LD和sitemap使用同一个资格规则，原53篇身份/正文/语言资格不意外退化。
4. 实际NTE Worker候选网络采样和桌面/手机浏览器确认无空正文、链接可用；Main公开JSON、另一游戏及旧资源保留。
5. 在N04验收前继续拒绝NTE新增，不仅改一个game白名单就放行。

### N05：NTE新增是一条完整交付，不是又一个fixture

范围：沿用原神additive合约的稳定身份/不可变来源/审批/确定顺序/公开A保留/恢复404语义，增加NTE适配，保持无媒体/固定元数据的小切片。

验收：

1. editor只能草稿，reviewer/admin才能批准；同ID碰撞、错game、来源模板变化、活跃锁和未批准导出均拒绝。
2. 导出真实CMS正式记录；新增只增加本篇，既有53篇NTE公开A及原神公开JSON保留。不能用Git原始O覆盖当前公开A。
3. 候选/恢复两owner实际构建和精确四版本云预览通过；新增前缺失URL真实404/noindex，无文章canonical/JSON-LD，旧URL均保持。
4. 代理策划一篇有实际用途的中文NTE攻略，先CMS草稿/重读/批准，再新run完整发布、公网采样/source-advance及Genshin共享Main交接；不重发旧releaseKey。
5. 失败注入先做隔离transport/loopback的两owner、超时和未知结果矩阵。真实partial/回滚继续独立记录，不主动故障生产凑验收。
6. 发布后刷新联合冷备/私有异地密文并认证恢复；安装、源码、publisher与当前数据的身份分别记录，不宣称整机重建。

### N06：把“拒绝隐式回退”发展成明确产品语义

当前R35保护有效但只会拒绝，不自动保留A；hold或CMS撤回不等于网页撤下，用户精确恢复到O也被保守阻断。先明确这些状态，不放松旧拒绝测试。

验收：以导入O、可信公开A、新批准B三方为基础，未触及字段保留A，只有显式批准意图才能reset；出现来源/并发漂移即拒绝。网站撤回另含删除/重定向/410或404、列表/搜索/sitemap/JSON清除与恢复合同。未经N06不得把CMS delete接口当公众删除功能。

### N07：减少日常手工拼装，不建设通用平台

现有真实入库主要通过认证REST加批次脚本，通用编辑CLI尚未交付。若后续内容批次频繁，封装薄命令：读取正式/草稿 -> 生成逐字段计划 -> 保存草稿 -> 重读 -> 显式批准 -> 调用既有发布器。凭证不出私有目录，不允许覆盖锁或SQL改业务表。

验收：重入不会重复创建记录，不丢其他语言；重读updatedAt只算漂移检查，不冒充服务端CAS。按单写者串行运行；需要多人编辑时再做真正CAS及冲突UI。发布、备份和恢复状态可追溯，但不把published自动连接到无监督云切流。

备份优先做“最近一次成功发布是否已有认证外部备份”的新鲜度检查和可恢复范围说明；自动冷备会短暂停CMS，应先明确维护窗口。无人值守计划、RPO/RTO和保留策略是独立交付，不在本轮擅自创建定时任务。

### N08/N09：长期平台工作，按价值单独启动

1. 每次只接管一个有明确用途的内容类型/owner，例如材料或版本/活动；先核对消费者/关联/多语言/媒体权利，再做DTO、草稿、导出、双源对账和小批真实交付。不能把全部只读导入转换成批量批准。
2. 普通请求全链releaseKey与ReleaseMap保持未完成。先用ADR比较“继续封存Worker顺序发布”与“版本化内容存储/请求固定release”的成本、缓存/RSC/SEO/媒体一致性和故障行为；只有确有免重建/关联一致性需求时实施，不能为关闭旧表格先建新存储。
3. 受控批量/队列需有去重、抢占、幂等、死信、超时、显式失败对账和告警；云写结果未知不自动重试。新游戏配置化和旧入口停写/最终同步/权威移交依次独立验收。
4. 平台审批/分支保护、账户级发布权限、预算可观测性、未知外部UUID来源及编码NUL/点段公网契约保留独立待办。不把七服务保护集称为全账户权限隔离，也不把历史10Worker观察当实时控制面。

## 4. 下一轮具体动作

**先执行N01，随后N02/N03，再进入N04/N05。** 第一轮限定改动应只涉及两游戏指南安全序列化、对应浏览器/消费者测试和验证型CI，保留已有发布保护。不得在同一批混入账号开启、全量CMS迁移、历史证据清理或Router改版。

每项状态以“源码实现 -> 自动回归 -> 精确提交CI -> 必要安装 -> 真实受影响owner发布/验收”分栏更新；不满足最后一栏时只关闭前面子项。审计结束时N01-N09均未启动；随后按用户要求执行五个分组的源码与隔离验收，状态见上表及[执行记录](../reports/project-next-phase-2026-11-05/README.md)。空间不足14GiB，未开始重型双owner构建、安装或发布；NTE新增正式门禁与R35生产reset拒绝仍保留，不能称五项全部完成。
