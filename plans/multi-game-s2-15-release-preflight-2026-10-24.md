## 1. 本批结论

本批实际推进 S2.14 所要求的集中发布预检，不重复内容撤回微批次。
发现既有 staging 只验收通用运行时，没有覆盖累计内容修复，先补齐正式云端验收入口。
随后完整读取线上四个独立 sitemap，发现蓝色星原六个重复项；本地修复并复验双环境。
进一步检查迁移差分，发现 NTE 57 个物品详情实际仍由 Main 承载，候选 sitemap 却遗漏其三语 171 个 URL。
该问题尚未修复；增加封存前纯本地覆盖门禁，当前明确拒绝发布，独立子图也仍有重复，因此**不 push、不启动 Actions、不部署任何 Worker**。
这不是线上已完成；既有整游戏归属假设确有缺陷，已在正式发布前识别并阻断，不能把它只当作外部依赖。

本批交付的是可重复执行的门禁、预检证据、最小修复和发布顺序。
未恢复账号、修改数据库/路由配置、合并 Worker、清除 CDN 缓存或删除历史证据。
原始脏工作区不变，继续在独立工作树实施。

## 3. 新增持久门禁

### 3.1 同一内容断言进入云端

`managed-content-smoke.mjs` 保留原本只允许 `http://127.0.0.1:PORT` 的认证夹具入口；另增固定两域名的发布验收入口。
二者共用公开 JSON、来源复核页、列表/详情/工具导航、CN 入口、情报面板、搜索、旧图片和 items 边界的断言。
受管浏览器检查有 20,000 次同源请求预算，站外资源继续阻断，不额外访问官方站点或外部 CDN。

远端仅向 IndexNow 发送一次无凭据请求并要求 401 + Unauthorized，不带真实 token、cookie 或合成 trusted-IP。
编译代码检查确认没有旧外部 transport；本地合成 token 继续验证认证后暂停及参数拒绝。
必须区分这三种证据，不能把远端 401 写成已经实测认证后的 503 暂停。

`web-staging-acceptance.mjs` 在现有运行时验收后调用完整内容验收。
新增固定正式域名的 `web-production-acceptance.mjs`，在正式推广后重复无账号 HTTP、运行时浏览器和受管内容检查。
两个部署 job 继续下载相同 artifact ID、检查相同 tar 摘要，不重建、不改写封存资产。

### 3.2 XML 不再只抽样一份子图

`web-published-sitemap-audit.py` 从封存产物 cache 读取 Main 的真实 XML 期望，要求云端根 index/主站子图 URL 集合一致。
再完整读取四个独立 owner 的实际子图并构造不相交并集，拒绝重复、错误 owner、非正式 URL、跨 owner 引用、编码路径别名、循环、过深/过多子图、DTD/entity 和过大响应。
额外前置检查从真实 NTE raw-materials 库导出 171 个仍属于 Main 的详情 URL；生产 build 在封存前运行 `local` 检查，不发云请求。
当前候选明确失败并保存缺失清单，阻止后续两个部署 job。远端入口也先执行它；本地内容测试通过不能覆盖这个发布拒绝。
这是暂时的失效关闭保护；下一阶段必须将 Router、导航、sitemap、XML 校验统一到路由级所有权，再取代整游戏假设，不能清空物品库或删掉断言。
预览要求 noindex，生产拒绝 noindex。

staging 读取 Main staging 的两份 XML，但独立 owner 仍读取正式域；报告明确分别标记 origin，不伪装成所有游戏都完成了 staging。
最多 40 份 XML、深度 3、每份 10 MiB、每 owner 50,000 URL；只允许固定域名和 sitemap 路径，GET 不跟随重定向。
这验证 XML 结构、集合和 owner，不逐条证明所有页面的 HTTP、语言正文、事实或图片授权。

staging、production 的结果 JSON 与完整 XML 集合报告在成功和失败时均保存到独立 GitHub artifact，保留 30 天。
失败会使发布运行失败，但不自动切回含旧 Roco 风险的版本。

| lvmeng | 27 | 27 | 结构读取通过，不据此认定全部事实已复核 |

根因在 `apps/game-azur-promilia/app/sitemap.ts`：两个目录已经由 pages 集合输出，又在结尾以另一组 priority/changeFrequency 输出。
保留原目录集合中的 weekly / 0.6 项，删除结尾六个重复项，去除两个无用 import；不靠最终 Set 去重掩盖生成错误。
本地真实 production、preview 构建均输出 150 条唯一 URL，与当次实际生产的唯一集合完全相等，增加 0、移除 0。
新增真实生成函数回归，同时给受控游戏本地 Worker 冒烟加上重复 loc 拒绝；这会在部署命令之前发现同类错误。

另一个全量验证发现：工作台旧测试仍要求生产 deploy/upload 以 Next 补丁检查开头，与 S2.4 已新增的前置内容门禁冲突。
调整测试为先内容门禁、再补丁检查、最后构建的准确顺序，不删除门禁、跳过测试或改变实际部署命令。

## 5. 索引迁移差分不能混为已上线

本轮实际生产根还是含 6,629 个唯一 loc 的旧 urlset，不是新根 index；新 Main 子图尚不存在于生产。
以本地 Main 4,344 个 URL 加当前四个独立 owner 的**唯一集合投影**得到 6,512 个页面，相对旧根新增 263、移除 380，净减少 117。
投影移除中包括 4 个应作为子图引用而非页面的 XML、120 个 Roco 核验/撤回路径、256 个 NTE 旧发现路径。
其中 171 个 NTE items 路径并非下线：Router 的 NTE_DETAIL_PAGES 不包含 items，实际回退 Main，三语 `/nte/items/annulith` 均为 200、index/follow、自身 canonical。
当前 Main 子图按 GAME_DEPLOYMENTS 整款游戏排除它们，独立子图也不收录，因此属于真实的发现路径遗漏，不能用“独立 Worker 接管”结案。
其余 85 个 NTE 日文路径应继续按具体 noindex/404/语言政策复核；已抽样角色为 noindex、一个无效攻略为 404，不把抽样推广为全部证明。
原神日文攻略抽样仍可读，独立语言政策有单独发布/strict-baseline 评审任务。
本轮保存差分及 HTTP/robots 抽样，不将净数量正确或子图 200 当作逐条索引迁移批准。
蓝色星原重复项仍未在线消失，投影去重仅用于看清差分，**不用于放宽严格门禁**。

## 7. 下一阶段发布顺序与停止条件

1. 先修路由级 owner 合同，恢复 Main 实际负责的 NTE 详情发现路径；联动调整现有禁止整个独立游戏出现在 Main 子图的 XML/测试假设。Router 行为不改、公开 URL 不变，新增回归证明 Main 回退与独立页面各有正确 owner。重新构建 Main、验收完整集合与差分；fallback gate 通过前不得云端上传。
2. 独立审查蓝色星原当前生产版本、精确来源/产物、累计待发代码和回滚兼容性；不能假定生产与本地仅差两行 sitemap。先形成该 owner 的范围和回滚证据。
3. 通过已有 `release:game` 受控入口，验证蓝色星原独立 staging 的索引保护、150 条唯一 XML、浏览器/资源；再按实际已核实 UUID 和精确服务名执行该 owner 的生产步骤。不得用 Main workflow 或手工 Wrangler 顺带部署。
4. 公网复查蓝色星原子图无重复且唯一集合不变，记录独立版本；确认其他 owner 和 Main 未意外变化。失败停在该 owner，不扩散至 Main。
5. 完成根/子图的实际迁移差分评审，单独保留 Genshin 语言策略及 strict-baseline 后续，不把 Main 上线当作它已生效。
6. 重新核对 main 漂移、Main 当前唯一版本、旧 artifact 有效性与摘要，再完成必要本地检查及预算说明。main 集成后使用现有显式 production workflow，先 staging 验收同一封存制品，全部通过才推广。
7. 推广后读取真实版本及 artifact 关联，复查公网内容/旧图/账号/缓存/资源/完整 XML/浏览器和观察窗口。若旧图基准 URL 仍被缓存服务，先定位缓存层，再按受控授权评审精确 purge；不预先全域清缓存。
8. 不用自动回滚隐藏内容纠错失败：旧 Main 版本会恢复已知旧内容。必要紧急回退需同时处理内容暴露，优先前向修复。

长期运营规则：共享域名发布的验收集合必须区分本次候选 owner 与未改变的生产 owner。
每个 owner 分别拥有版本、产物、回滚与验收证据，主站发现层必须检查全图，不能用首页 200 或减少净 URL 数量代替。
本次预检发现的独立依赖不应通过扩大单次发布故障域解决，也不应因节约 Actions 分钟而豁免。
