# Roco 竞品能力借鉴 PRD — 2026-09-07

> 目标：参考 `rocokingdomworld.org` 的信息架构与工具化能力，把 Gachia 的 Roco 子站从“多游戏资料库中的一个频道”升级为“玩家会反复回来使用的 Roco companion 入口”。

## 背景

`rocokingdomworld.org` 的核心优势不是页面数量，而是把 Roco Kingdom World 的玩家需求拆成了几个高频入口：

- 活动日历：展示 live、upcoming、ended 等活动状态。
- 旅行商人：聚焦每日/周期性刷新信息。
- 蛋识别/预测：承接 Roco 玩家强玩法需求。
- 地图：用大量 marker 和资源点形成长期留存工具。
- 首页数据量信号：直接展示 events、map markers、spirits 等规模感。

Gachia 已经有多游戏、多语言、角色库、攻略、地图、兑换码、日历等基础能力，短板是 Roco 子站的“专属工具感”和“今日行动入口”还不够强。

## 产品目标

1. 让 Roco 玩家进入 Gachia 后，30 秒内知道今天该看什么。
2. 增强 Roco 子站在搜索结果中的主题权威，覆盖活动、地图、宠物、蛋、商人、属性克制等垂直查询。
3. 用工具页和状态页提高回访率，而不是只依赖一次性攻略阅读。
4. 保持 Gachia 的多语言优势，所有新增入口至少覆盖 `zh`、`en`、`ja`。

## 非目标

- 不直接复制竞品页面结构、文案或视觉设计。
- 第一阶段不承诺实时自动抓取官方数据，优先做手动数据源可维护的版本。
- 不在 Workers 包体已经接近 3 MiB 的情况下继续把大体量 JSON 直接打进服务端 bundle。

## 用户画像

### 新玩家

想知道 Roco Kingdom World 是什么、怎么下载、开服后先做什么、哪些活动正在进行。

### 日常玩家

每天关心商人刷新、活动奖励、地图资源点、兑换码、宠物收集进度。

### 深度玩家

关注蛋孵化、属性克制、宠物图鉴、进化路线、培养优先级和地图路线。

## 核心需求

## P0：Roco 首页改造成“今日入口”

### 需求

在 Roco 游戏首页增加一组高意图工具入口，优先展示：

1. 今日活动
2. 商人刷新
3. 宠物图鉴
4. 地图探索
5. 兑换码
6. 下载/版本信息

每个入口应包含：

- 当前状态或数据量，例如活动数、宠物数、地图点数、兑换码状态。
- 明确下一步动词，例如查看、领取、探索、筛选。
- 多语言标题和描述。

### 验收标准

- `/zh/roco`、`/en/roco`、`/ja/roco` 均显示 Roco 专属入口。
- 首屏不再只像普通资料库导航，应能明显表达“今天可以做什么”。
- 不影响其他游戏首页。
- `pnpm --filter web type-check` 通过。

## P1：活动日历升级

### 需求

将 Roco 活动信息从普通列表升级为状态化日历/时间线：

- 支持 `live`、`upcoming`、`ended` 状态。
- 支持活动类型筛选，例如限时、福利、挑战、商店、签到。
- 展示活动起止时间、剩余时间、奖励摘要。
- 页面顶部展示“当前进行中”和“即将开始”的摘要。

### 数据要求

活动数据应独立于页面组件维护，便于后续接入自动更新：

- `id`
- `title`
- `titleEn`
- `titleJa`
- `status`
- `category`
- `startAt`
- `endAt`
- `rewards`
- `source`
- `updatedAt`

### 验收标准

- Roco 活动页支持状态筛选。
- 活动列表的标题、描述、奖励摘要有三语言。
- 空状态清晰，例如暂无进行中活动。
- 构建后 sitemap 能覆盖活动入口页。

## P1：Roco 专属工具入口

### 需求

第一批先做可维护、低风险的数据型工具，不强依赖复杂算法：

1. 属性克制表
   - 展示 Roco 属性之间的克制关系。
   - 支持按攻击属性或防御属性筛选。

2. 商人刷新页
   - 展示已知商人、商品、刷新周期、推荐购买项。
   - 暂无实时数据时显示“待核验”状态，而不是伪实时。

3. 蛋/孵化入口
   - 第一版可作为蛋种图鉴和孵化说明。
   - 后续再升级成 Egg Predictor。

### 验收标准

- 至少上线一个 Roco 专属工具页。
- 工具页有清楚的相关页面内链，例如图鉴、地图、活动、攻略。
- 数据缺失时不能编造，需要显示待核验或来源状态。

## P1：地图页增强内链

### 需求

在 Roco 地图页增加 related resources 区块：

- 宠物图鉴
- 材料/物品
- 活动日历
- 商人刷新
- 地图探索攻略

同时在地图页顶部增加数据量信号：

- 区域数
- marker 数
- 可收集宠物数
- 最近更新时间

### 验收标准

- `/roco/map` 页面能把用户导向图鉴、活动和工具页。
- 内链文案三语言覆盖。
- 无地图数据时显示可解释的空状态。

## P2：全站数据量信号标准化

### 需求

为重点游戏首页统一展示结构化数据量：

- 角色/宠物数量
- 攻略数量
- 地图区域或点位数量
- 活动数量
- 兑换码数量或最新核验日期

Roco 优先落地，后续扩展到 Aniimo、NTE、SEA、Wuwa 等游戏。

### 验收标准

- 数据量来自现有数据模块，不手写易过期数字。
- 多语言页面展示一致。
- 不显著增加 Cloudflare Worker bundle 体积。

## P2：免责声明与来源状态优化

### 需求

Roco 子站页面统一强化：

- 非官方粉丝站说明。
- 数据来源与最近更新时间。
- 对“待核验”“预测”“官方已确认”进行明确区分。

### 验收标准

- 页面不会让用户误以为 Gachia 是官方站。
- 预测/待确认内容有清晰标识。
- 适用于 Roco，后续可复用到其他游戏。

## 信息架构建议

### Roco 首页

第一屏建议顺序：

1. 当前进行中活动
2. 今日商人/刷新
3. 宠物图鉴入口
4. 地图探索入口
5. 兑换码状态
6. 下载与版本入口

### Roco 工具页

建议新增或强化的路径：

- `/roco/events`
- `/roco/merchant`
- `/roco/type-chart`
- `/roco/eggs`
- `/roco/map`
- `/roco/characters`
- `/roco/redeem-codes`

### 页面互链

- 活动页链接兑换码、商人、地图。
- 地图页链接宠物图鉴、材料、活动。
- 宠物详情页链接属性克制、进化线、地图。
- 商人页链接材料、活动、地图。

## 内容与 SEO 要求

### 标题策略

每个重点页都应覆盖中英文核心查询：

- Roco Kingdom World events
- Roco Kingdom World codes
- Roco Kingdom World map
- Roco Kingdom World merchant
- Roco Kingdom World egg
- Roco Kingdom World pets
- 洛克王国世界 活动
- 洛克王国世界 兑换码
- 洛克王国世界 地图
- 洛克王国世界 宠物

### Meta 要求

- title 控制在合理长度，避免 webmaster 报“标题太长”。
- description 至少说明页面用途、数据范围、更新状态。
- H1 必须存在且唯一。
- 图片必须有 alt，工具页图标可用 aria-label。

## 技术约束

1. Cloudflare Workers gzip 包体已接近 3 MiB，新增大数据必须优先考虑：
   - 静态 JSON assets
   - 分页加载
   - 按游戏动态导入
   - 客户端按需加载工具数据

2. 不把大型地图 marker 或完整图鉴重复塞进多个页面 bundle。

3. 多语言文案应集中管理，避免页面组件内散落大量重复字符串。

4. 新增路由前先确认 `generateStaticParams` 对页面数量和构建时间的影响。

## 实施计划

## Phase 1：入口重排

- 增强 Roco 游戏首页的今日入口模块。
- 增加数据量信号。
- 给现有 map、characters、redeem-codes、version、download 页面补 Roco 专属导流。

预计收益：

- 最快提升玩家首屏体验和站内二跳。
- 实现成本低，不依赖新数据。

## Phase 2：活动与商人

- 建立 Roco events 数据结构。
- 建立 Roco merchant 数据结构。
- 上线活动状态筛选和商人刷新页。

预计收益：

- 承接竞品最强的日常回访需求。

## Phase 3：专属工具

- 上线属性克制表。
- 上线蛋/孵化图鉴。
- 将宠物详情页与工具页互链。

预计收益：

- 形成 Gachia 的 Roco 功能差异点。

## Phase 4：性能与部署保护

- 审计新增数据是否进入 Worker bundle。
- 对大型 JSON 做 assets 化或按需加载。
- 重新跑 OpenNext dry-run，确保 gzip 低于 3 MiB。

## 指标

上线后优先观察：

- Roco 首页到工具页点击率。
- `/roco/events`、`/roco/map`、`/roco/characters` 的自然搜索入口增长。
- 兑换码、活动、地图页面的停留时间。
- Search Console 中 Roco 相关查询的曝光和 CTR。
- Cloudflare Worker gzip 包体变化。

## 风险

- 如果官方数据更新频繁，手动维护活动和商人信息可能滞后。
- 如果地图 marker 数据过大，可能继续压缩 Workers 包体余量。
- 如果 Roco 专属工具路由过多但数据不足，容易形成薄页面。

## 决策建议

先做 Phase 1，再做活动/商人。原因是 Phase 1 能最快利用现有数据改善体验，并且能为后续新增工具预留入口；活动和商人需要更稳定的数据维护策略，不宜一开始就做复杂自动化。
