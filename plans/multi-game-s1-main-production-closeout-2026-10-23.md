## 4. 云端对账、观察与成本

生产发布后，九个服务 settings、生产 routes/domains 均与基线一致。只有主站及既有主站 staging 的版本/deployment 变化；四个游戏、生产 Router、Router staging、蓝色星原 staging 保持原版本。旧主站 UUID 元数据仍可读取；未执行真实生产回退演练。

观察以平台部署时间为起点，CI 立即执行生产探针，独立探针在约 +182 秒启动，后续于 +300 / +600 秒复核，三批各 34 项均无失败。Cloudflare adaptive Workers 在 14:50:43–15:00:57 UTC 窗口报告主站 914 次请求、148 次 subrequest、0 次 Worker 异常；包含本次探测流量，存在采样/聚合延迟，不等于所有 HTTP 错误或用户体验错误均为零，也不是连续覆盖所有请求或真实用户 SLO。最终统计见 `reports/release-safety/s1-main-production-verification-2026-10-23.json`，原始证据保留在被忽略的 `.release-records/s1-production-readiness/`。

本阶段共 4 次 Actions：2 次 push 验证、1 次发布前安全拦截、1 次成功正式请求。按作业开始/结束时间累计约 49.4 个 Linux runner 墙钟分钟；按每个作业向上取整约 52 分钟，仅为运行量估算，不是账单。账户 billing 额度 API 因当前令牌缺少 `user` scope 无法读取，未扩大权限或声称剩余额度充足。浏览器安装耗时波动及兼容修复使结果高于首次 25–40 分钟估计，已在追加运行前说明风险。

已有封存 tar、历史证据和官方 CLI 测试副本保留，不自动清理。新构建与证据增加了本地/Actions 存储用量，本轮不宣称节省磁盘空间。结项报告只本地提交，不因纯文档再 push/触发 Actions。

## 5. 残余风险与下一阶段

1. 此次只完成主站限定生产推广，其他游戏线上仍是各自既有构建；后续运行时升级应逐一 staging 验收，不顺手批量发布。
2. 旧主站回退会恢复旧登录入口；向前保留旧 chunk 不证明回退后所有新标签页的 lazy chunk 均兼容。严重回归应按计划仅回退主站并提示刷新，不能删除数据/secret 掩盖问题。
3. 旧资源仍可能递归累积，新 artifact 的 30 天保留不是永久备份；过期前应按发布频率评审保全与 GC 预演，当前没有自动删除。
4. GitHub environments 缺少独立审批、upload/download-artifact v4 的 Node 20 迁移警告及既有 lint 警告记录为后续维护事项；本轮没有为了消除警告增加发布或放宽门禁。
5. GSC/CWV、长期错误率/CPU/费用、索引冲突和内容新鲜度仍未完成全量验收。下一主工作包按 S2 推进内容单一来源、镜像/消费者对账和 sitemap/语言契约；存储只先做引用保护与清理预演，不直接删除。

执行决策与首次失败的详细说明见 [发布计划](multi-game-s1-main-production-release-2026-10-23.md)；长期主文档升级为 v1.6，保留历史审计基线，不将本轮结果冒充初始只读审计事实。
