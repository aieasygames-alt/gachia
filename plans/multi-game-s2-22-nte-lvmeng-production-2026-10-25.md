## 交付顺序

1. 收紧 owner 配置白名单和整包封存；复用已有完整树校验，不开放通用远程发布权限。
2. 为生产包增加 workers.dev 主机运行时 noindex/robots 阻断，使同一包可用于版本预览和正式。
3. 修复绿梦两套浏览器清单的读写拒绝异常；保留旧 key 和未知字符串 ID，验证畸形输入、拒绝存储、重载持久性。
4. 本地测试、类型检查、生产构建、资源命名空间与旧静态保留、dry-run、真实本地 Worker HTTP/浏览器验收。
5. 逐游戏上传版本但不切流；确认部署、绑定、路由、域名及非版本设置未改变，校验版本特定预览的页面和资源。绿梦必须显式选择 production 环境，保留已有服务标签。
6. 验收通过后只将已验证 UUID 切至 100%，不重新构建；逐项正式验收后才处理另一个游戏。
7. 最终全站 owner/XML 图与跨游戏回归、云状态对账、发布报告和长期文档更新。

## 必须通过的门禁

- 源码已提交且构建期间不变，完整产物清单及外部 SHA pin 不变。
- 候选 sitemap 与旧正式 URL 集完全相同：异环 389，绿梦 27；全站六份 XML 合集预计 6653，异环 Main 自有 171 条 items 详情保留。
- 异环未完成的日文保持 noindex，只有满足现行质量阈值的攻略进入日文索引与 hreflang；绿梦保持仅中文。
- 所有 sitemap 页面、对应异环日文页、canonical、hreflang、JSON-LD、真实 404、预览 robots/noindex 均验证。
- 所有旧/新 JS/CSS/font 在命名空间及原路径逐字节核对；正式原路径在独立 Worker 验证，不能误用 Main 的 `/_next`。
- 桌面/移动、交互/延迟脚本/无 JS、筛选和客户端跳转、绿梦本地进度、账号请求禁用，均保留真实浏览器诊断。
- 旧云 renderer + 新旧资源并集必须做本地兼容性检查；它不是线上回滚演练，原始版本 UUID 回退也不能证明新缓存 HTML 的资源仍可用。

## 已知限制与失败记录

- 初次捕获误要求原始 subdomain API 返回 Wrangler 组合出的 preview suffix，门禁失败且未发生写操作；保留失败日志，改为验证真实 enabled/previews_enabled 字段。
- 旧 SEO parity 脚本缺少预览地址时拒绝运行；其全页要求 ja hreflang 的旧契约也不适用现有日文抑制策略。本阶段用严格的逐页索引/语言与版本预览验收替代，不把旧脚本记为通过。
- GitHub 独立审批保护仍是既有运维风险；本阶段操作人授权和本地证据不等同独立审批或远程构建证明。
- 异环首轮正式验收在完成 504 页/170 次资源后，因未知栏目预期 404 而实际 301 安全停止。Main middleware 的既有 NTE allowlist 明确将该路径重定向 `/zh/nte`，角色详情缺失仍为 dedicated 404。只修验收契约并补回归，不重新 build/upload/deploy；首轮 failure 原样保存。工具提交与业务制品源码分别记账，后续只允许经审查的验收脚本/测试/本阶段计划差分，不允许应用、数据或制品改动。

## 扩展图片巡检与遗留

45 张公共图片中 44 张通过，`/images/characters/chaos.webp` 由 Main 承载且仍返回 404。使用实际捕获的旧生产模块本地还原，旧 renderer 与候选均引用相同缺图路径，证明不是本次候选改变图片 URL 所致；图片巡检 failure 原样保留，未改名为全绿。专属 Worker/版本预览只带 logo，预览截图可能缺 Main 共用肖像；正式域名另有图片验证，不能混为一谈。

本阶段不虚构图源、不发布无来源图片、不为了该既有缺口重发无关 Main。下批应选择经核实的正式图源或明确占位图策略，连同独立站搜索、部分原神元数据/导航、历史来源、异地恢复和容量治理继续处理。没有磁盘删除、Worker 合并、数据库变更或线上回滚演练。
