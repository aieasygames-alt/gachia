# GSC 内容质量提升计划：Genshin / HSR / Wuwa / ZZZ

## 目标与范围

本计划针对 GSC 最近 7 天导出（2026-09-06 至 2026-09-12，Web 搜索）中贡献展现和点击最多的四个游戏：

- 原神（Genshin Impact）
- 崩坏：星穹铁道（Honkai: Star Rail / HSR）
- 鸣潮（Wuthering Waves / Wuwa）
- 绝区零（Zenless Zone Zero / ZZZ）

当前阶段只做内容质量提升：先保证搜索者进入页面后能得到完整、可信、可执行的答案，再做规模扩张和新页面生产。

## 统一内容质量门槛

每篇高贡献页面在发布前必须通过以下检查。未满足任何一项，不进入下一轮扩写：

1. **首屏答案**：用户搜索的核心问题在标题下方 200–300 字内得到直接回答；不能要求用户先读背景介绍或滚动到表格。
2. **时间与版本**：显示 `Updated`、当前版本/周期和数据来源；时效内容必须能明确区分当前、已结束、即将开始、预测。
3. **范围声明**：说明覆盖区域、模式、角色池/武器池、语言和数据截止时间；预测内容必须标注为预测。
4. **可执行结论**：每个页面至少提供“现在该做什么、资源如何分配、什么情况下不要做”的行动建议。
5. **证据与不确定性**：官方确认、站内计算、社区观察和编辑推断分开书写；不能把未核实爆料写成事实。
6. **深度而非字数**：内容必须覆盖定义、决策、例外、替代方案和 FAQ；不以机械增加字数作为完成标准。
7. **内部闭环**：从页面可到达角色、武器/装备、队伍、Tier List、兑换码或版本中心；链接文本必须说明下一步价值。
8. **移动端可读性**：首屏答案、关键表格、CTA 和更新时间在移动端不被折叠或横向滚动阻断。
9. **多语言一致性**：英文页面不得只有中文内容的直译；三种语言都要覆盖各自用户的核心查询词和时间口径。
10. **质量回归**：改版前后记录 URL、主要查询、展现、CTR、排名、更新时间和内容变更，避免只看点击总量。

## 逐游戏审计与改写计划

### 1. Genshin Impact

**GSC 优先信号**

- `/en/genshin/guides/banner-schedule-guide`：14,977 展现、CTR 0.68%、排名 9.54。
- `genshin next banner`：2,908 展现、CTR 0.65%、排名 9.47。
- `/en/genshin/guides/snezhnaya-version-guide`：2,146 展现、CTR 0.05%、排名 8.49。
- `/en/genshin/guides/cross-game-comparison-guide`：2,276 展现、CTR 0.62%、排名 7.06。

**逐页检查顺序**

1. Banner Schedule：首屏列出当前祈愿、下一个祈愿、复刻状态、结束时间、保底规则、原石预算和“适合谁抽”。每个角色必须链接角色页、配队和材料页。
2. Version / Snezhnaya：回答版本时间线、区域/系统变化、玩家现在该准备什么；把已确认内容与待确认内容分栏。
3. Tier List：按深境螺旋、大世界、低命/低成本和队伍缺口分层，不只给 SS/S/A/B。
4. Characters：补齐角色定位、关键命座、替代武器、队伍样例、材料路线和“适用/不适用场景”。
5. Map / Materials：每个区域或材料点提供获取条件、路线、刷新/消耗说明，并从角色页反向链接。

**验收标准**

- Banner 页面首屏可回答 `current banner`、`next banner`、`rerun`、`when does it end`、`should I pull`。
- Genshin 高展现页面中，主要查询至少各有一个明确段落或 FAQ，而非仅出现在标签。
- 角色推荐必须能从“评级”追溯到队伍角色、成本和版本环境。

### 2. Honkai: Star Rail

**GSC 优先信号**

- `/en/starrail/guides/banner-schedule-guide`：9,271 展现、CTR 0.52%、排名 8.17。
- `honkai star rail tier list`：2,677 展现、CTR 0.19%、排名 8.18。
- `hsr tier list`：1,282 展现、CTR 0.31%、排名 9.35。
- `hsr banner schedule`：1,084 展现、CTR 0.83%、排名 6.45。

**逐页检查顺序**

1. Banner Schedule：分开说明角色跃迁、光锥跃迁、复刻、版本阶段、星琼预算和保底；加入“角色优先还是光锥优先”的条件决策。
2. Tier List：按忘却之庭、虚构叙事、末日幻影、日常/自动战斗分别解释；注明队伍绑定、速度/命途要求和低配置替代。
3. Team Builder：输出角色职责、速度轴/能量循环、关键光锥和替代角色，不能只显示四个角色名称。
4. Fate / 版本专题：把联动时间、兑换码、奖励和抽取规划放在一个时间线，过期信息必须显式标记。
5. Character / Light Cone：补充适用队伍、遗器/配速前提、替代方案和投入回报。

**验收标准**

- Tier List 每个评级至少附场景、队伍依赖和资源成本说明。
- Banner 页面能区分“当前可抽”与“已确认但未开放”，避免用户误判。
- Team Builder 结果可以解释为什么推荐，而不是只有静态列表。

### 3. Wuthering Waves

**GSC 优先信号**

- `/en/wuwa/guides/banner-schedule-guide`：12,320 展现、CTR 0.75%、排名 8.43。
- `wuwa banners`：2,621 展现、CTR 0.15%、排名 8.80。
- `wuwa next banner`：529 展现、CTR 0.38%、排名 8.92。
- `/en/wuwa/guides/farming-guide`：2,082 展现、CTR 0.96%、排名 6.66。

**逐页检查顺序**

1. Banner Schedule：明确角色池/武器池分别的保底、当前/下期/复刻、结束时间、星声收入和抽取优先级。
2. Version / Platform FAQ：回答 3.x 版本状态、Steam/Xbox/移动端差异、控制器与下载问题；只写官方已确认的平台事实。
3. Farming Guide：按角色突破、武器、声骸、技能材料给出路线、体力优先级和每日/每周限制。
4. Tier List：同时考虑主 C、协同、声骸成本、操作难度和探索价值，补充低配队伍。
5. Map / Characters：角色需求反向链接到材料路线，地图点位必须标明前置任务或解锁条件。

**验收标准**

- Banner 页面首屏直接展示 current/next/upcoming，而不是只有长篇说明。
- 角色池与武器池不混用预算或保底解释。
- 新玩家从版本/平台页能在两次点击内进入下载、兑换码、角色和养成路线。

**GSC 优先信号**

- `/en/zzz/guides/banner-schedule-guide`：12,784 展现、CTR 0.27%、排名 9.10。
- `zzz next banner`：1,902 展现、CTR 0.05%、排名 9.42。
- `zzz upcoming banners`：1,064 展现、CTR 0.56%、排名 9.26。
- `zzz team builder`：1,074 展现、CTR 10.89%、排名 4.70。
- `/en/zzz/teams`：4,455 展现、CTR 5.97%、排名 6.88。

**逐页检查顺序**

1. Banner Schedule：展示代理人、音擎、当前/下期/复刻、结束时间、菲林预算，并说明代理人优先于专属音擎的条件例外。
2. Team Builder / Team Building Guide：按强攻、击破、异常、支援、生存位解释组合；展示循环、替代角色、驱动盘和资源路线。
3. Tier List：分离深渊/式舆防卫、日常、低配和高投入场景；评级必须连接到队伍而非脱离环境。
4. Drive Disc / Farming Guide：回答刷取顺序、主词条、套装替代、体力投入和新手过渡。
5. Version 3.x / Launch Hub：把版本日期、新代理人、直播码状态、Steam/Xbox/下载 FAQ 放在统一时间线，过期码保留但明确不可用。

**验收标准**

- `zzz next banner` 页面首屏必须告诉用户下一个代理人是谁、何时开始、需要多少菲林以及适合哪些队伍。
- Team Builder 每个推荐队伍包含角色职责、循环、替代位和最低养成条件。
- Tier List 的每个高评级角色至少链接一个实际队伍和一个配装/驱动盘入口。

## 执行阶段

### 阶段 0：建立审计表（1 个工作日）

为四个游戏各建一张页面清单，字段包括：URL、游戏、页面类型、主要查询、展现、点击、CTR、排名、版本、更新时间、首屏答案、证据来源、缺口、负责人、状态。

### 阶段 1：高展现低 CTR 页面（2–3 个工作日）

依次处理 Genshin → HSR → Wuwa → ZZZ 的 Banner Schedule，再处理对应 Tier List 和版本中心。每页先做内容审计，再改正文、FAQ、表格和内部链接，最后更新元数据。

### 阶段 2：高 CTR 工具页深度（2 个工作日）

优先扩展 ZZZ Team Builder，再复制验证到 HSR、Genshin、Wuwa。工具输出必须增加解释层：推荐原因、替代角色、资源代价、适用模式。

### 阶段 3：角色与养成闭环（持续迭代）

从 GSC 查询反推缺少的角色页、材料页、装备页和地图页；每新增一个主题，必须接入至少一个 Banner/Tier/Team 页面，避免孤立文章。

### 阶段 4：质量与 GSC 回归

每次改版后 7 天、14 天、28 天分别复查：

- 目标查询 CTR 是否提升
- 平均排名是否保持或提升
- 页面点击是否增长而非只靠整体展现上涨
- 新增 FAQ/内部链接是否带来相关查询扩展
- 美国与移动端的 CTR 是否改善
- 是否出现内容过时、错误版本或用户意图漂移

## 统一验收模板

每页提交时附以下记录：

1. 改版前后 GSC 指标快照。
2. 目标查询与对应正文段落/FAQ 的映射。
3. 事实来源和更新时间。
4. 首屏截图（桌面、移动）。
5. 内部链接清单及链接目标。
6. 已知不确定性和下一次复查日期。

## 暂不做的事项

- 暂不以大量新增页面替代现有页面质量修复。
- 暂不把未核实泄露、社区传闻或预测写成官方事实。
- 暂不为追求字数加入与查询无关的泛 SEO 段落。
- 暂不根据单周波动判断内容成功，至少观察 7/14/28 天窗口。
