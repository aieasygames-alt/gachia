# Payload V1 有限完成计划

日期：2026-11-03，R30。当前执行清单以本文为准；完整历史范围仍见[任务表](project-task-status-current.md)。本轮见[R30单机范围与恢复验收](../reports/payload-single-host-closeout-2026-11-03-r30/README.md)，首发停止点见[R29](../reports/payload-real-lifecycle-2026-11-03-r29/README.md)，操作见[手册](../docs/payload-operator-runbook.md)。

## 1. 完成的定义

本轮目标不是再扩建 CMS 平台，而是交付**本机单用户编辑、Genshin/NTE 既有指南文字可持续安全发布**。用户已明确 Payload CMS 只在这台 Mac 运行；第二台 Mac、跨机安装/启动/迁移不属于限定 V1 验收条件。Payload/PostgreSQL 保留在本机，公众请求继续由 Cloudflare 多 Worker 服务，不依赖 Mac 在线。内容事实准确度、翻译补齐不作为首发门槛。

- **首次可用发布**：C03 的首次真实 Genshin 编辑已从 CMS 经双 owner 构建/云预览/推广，公网验收通过并持久化证据；这不等于稳定 V1 完成。
- **稳定限定 V1**：C01–C05 全部满足关闭条件，包括连续发布、恢复后再次发布、NTE/共享 Main 连续性，以及本机恢复与独立密钥托管；不要求跨机运行。独立密钥保护整机故障时的解密能力，不等于要求另一台 Mac 托管 CMS。
- **原始项目完整完成**：全类型、全 scope、全 owner、完整 ReleaseMap/请求一致性与权威移交/退役等原始任务验收完成。稳定 V1 不能替代 P0–P7 / T01–T12 的全范围完成。

不以新增测试数、报告轮数、工具数量或同机重复演练衡量进度；每轮关闭一个下表的明确缺口。C02工程关闭后，不因本地真实编辑尚不存在而反复执行已有A/B演练或新增首发便利工具。

## 3. 执行顺序与停止扩建规则

1. **C02工程子项关闭，不再扩建准备工具**：已实现最窄的恢复来源交接，复用现有验证与来源目录；精确提交CI身份以R28 delivery为准。真实恢复→接续→再发尚未验收，归C03/C04而非又开一个便利命令任务。
2. **先修复C03精确版本取证，再推进首发**：R29实际GET证明旧UUID选择器返回最新模块，R30文档/SDK核验及production environment内容GET没有找到可靠替代下载。不要再穷举无依据的选择器。按[取证收敛方案](../docs/payload-version-provenance-2026-11-03.md)处理上传时封存与历史取证；方案尚未实现/安装，当前仍fail closed。不能把ETag当模块SHA、把本地字节冒充新鲜下载、把活动UUID换成非活动UUID或跳过四版本重验。旧run保留，只对新run重新执行全部门禁；不删journal/自动重试，不延长15分钟门禁。
3. **完成 C03 连续/恢复链，再 C04**：有下一条真实编辑才发布下一次；无编辑时记录等待输入，不制造变化。C02 的实际恢复接续应在同一生命周期内验证。
4. **C05a关闭，不再重复恢复凑进度；独立目的地具备即做C05b**：用户不需要第二台Mac。独立key目的地可为适当的离线介质或既有安全托管，不必运行CMS；当前未配置，不能擅自上传到iCloud/报告/密文桶。最新备份与同机启动通过不等于整机丢失后可解密。
5. **C01–C05 关闭后冻结限定 V1**：只保留缺陷修复、依赖复核及日常发布维护，再按原始范围另排下一里程碑。不要重新开启架构选型/已有本地连续发布/历史 staging 调查。

每个工作包的交付必须说明：实现、模拟或实际网络验收、安装、真实云验收分别是否完成。只验证 CI 通过不能作为生产验收。

## 5. 不改变的多 Worker 边界

当前观察10个 Worker，推广保护集7个，每次只写 `[game, main]`；Router和staging不在发布写入目标。Genshin/NTE指南 HTML 属于各 game Worker，`/data/<game>/raw-guides.json` 属于 Main。两 owner 顺序推广不是原子事务，partial failure必须停止并显式恢复。公众网站无 CMS Tunnel、无 Mac 回源依赖。本清单不新增 Worker、云存储产品或公网 CMS。
