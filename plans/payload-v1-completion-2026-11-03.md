# Payload V1 有限完成计划

日期：2026-11-03，R27。当前执行清单以本文为准；完整历史范围仍见[任务表](project-task-status-current.md)。证据见[R27审计](../reports/payload-completion-audit-2026-11-03-r27/README.md)，操作见[手册](../docs/payload-operator-runbook.md)。

## 1. 完成的定义

本轮目标不是再扩建 CMS 平台，而是交付**本机单用户编辑、Genshin/NTE 既有指南文字可持续安全发布**。Payload/PostgreSQL 保留在 Mac，公众请求继续由 Cloudflare 多 Worker 服务，不依赖 Mac 在线。内容事实准确度、翻译补齐不作为首发门槛。

- **首次可用发布**：C03 的首次真实 Genshin 编辑已从 CMS 经双 owner 构建/云预览/推广，公网验收通过并持久化证据；这不等于稳定 V1 完成。
- **稳定限定 V1**：C01–C05 全部满足关闭条件，包括连续发布、恢复后再次发布、NTE/共享 Main 连续性，以及独立密钥和跨机恢复。
- **原始项目完整完成**：全类型、全 scope、全 owner、完整 ReleaseMap/请求一致性与权威移交/退役等原始任务验收完成。稳定 V1 不能替代 P0–P7 / T01–T12 的全范围完成。

不以新增测试数、报告轮数、工具数量或同机重复演练衡量进度；每轮关闭一个下表的明确缺口。若本地真实编辑尚不存在，继续推进 C02，不反复执行已有 A/B 演练或新增首发便利工具。

## 3. 执行顺序与停止扩建规则

1. **下轮只做 C02**：先为实际恢复 journal/来源身份契约写失败测试，再实现最窄的恢复来源交接，复用现有验证与来源目录。完成实现/隔离测试/安装/Git-CI后，该工程子项关闭，不因为尚无真实编辑继续增设便利命令。
2. **候选出现即优先 C03 首发**：不等待 C05 或全类型迁移；一旦开始云操作，按同一 run 的门禁完成或进入显式恢复，不穿插来源代码改动。
3. **完成 C03 连续/恢复链，再 C04**：有下一条真实编辑才发布下一次；无编辑时记录等待输入，不制造变化。C02 的实际恢复接续应在同一生命周期内验证。
4. **具备独立介质/第二 Mac 即做 C05**：本轮 `/Volumes/Antigravity` 为只读，另一个挂载卷为系统卷；这只是当前已挂载介质的观察，不声称穷尽用户所有远端安全托管方案。
5. **C01–C05 关闭后冻结限定 V1**：只保留缺陷修复、依赖复核及日常发布维护，再按原始范围另排下一里程碑。不要重新开启架构选型/已有本地连续发布/历史 staging 调查。

每个工作包的交付必须说明：实现、模拟或实际网络验收、安装、真实云验收分别是否完成。只验证 CI 通过不能作为生产验收。

## 5. 不改变的多 Worker 边界

当前观察10个 Worker，推广保护集7个，每次只写 `[game, main]`；Router和staging不在发布写入目标。Genshin/NTE指南 HTML 属于各 game Worker，`/data/<game>/raw-guides.json` 属于 Main。两 owner 顺序推广不是原子事务，partial failure必须停止并显式恢复。公众网站无 CMS Tunnel、无 Mac 回源依赖。本清单不新增 Worker、云存储产品或公网 CMS。
