## 1. 贯穿各阶段的稳定决策

- 保持公共域名和 `/{locale}/{gameId}/...` URL；内部部署变化不直接改变公开地址。
- 每个页面只有一个逻辑 owner；语言、canonical、robots 与 sitemap 使用同一页面契约。
- 源内容唯一；镜像、搜索、PageManifest 是可验证的派生物。
- GameManifest 表达稳定能力；ContentRecord 表达内容与证据；ReleaseRecord 表达版本和实际发布状态。
- 公共内容与用户私有数据隔离，SEO 正文服务端可读取。
- 当前版本不提供站点登录或账号云同步，保留无账号本地工具与历史数据；停用验收不能以跳过接口测试代替，恢复账号另开切片。
- 初期使用现有单仓库、应用、存储与脚本；不预设最终 Worker 数量，不先新增数据库或大型 CMS。
- 未知变更扩大验证；任何优化不得绕过生产审批、回滚和线上核验。
- 每个切片都包含真实使用路径、失败路径、证据和回退方式；测试通过不等于已部署。

## S0：建立可复现基线与试点边界

**用户故事：**U01、U09。

**业务结果：**明确从哪个版本、哪些内容和哪些服务开始，避免把脏工作区差异当成生产状态。

### 建设内容

固定实施输入、试点游戏、区服、语言、代表页面与失败样例；在允许范围内核实当前生产版本、环境和预算。记录审计缺少的指标，无法获取的明确保留未知状态。

### 验收标准

- [x] 当前工作区既有修改受到保护，实施使用独立且可追溯基线。
- [x] 试点选择有依据：有真实内容维护需求、范围可控，不同时迁移所有游戏。
- [ ] 基线包含首页、列表、详情、404、索引、资源、跨应用导航和一项核心操作。
- [ ] 记录生产配置与实际线上状态的差异；未获云读取权限时不得声称核实。
- [ ] 成本、性能、包体指标标明时间、测量条件、来源与缺失项。
- [ ] 后续批次允许动作、失败停止条件和验收责任明确。

**演示：**展示一个试点的基线卡片，能回答“当前是什么、要改变什么、不能改变什么”。

**回退：**仅记录，不改变承载和数据；发现基线不可信则停止后续推广。

## S1：安全预览与明确发布状态

**用户故事：**U01、U07。

**关联需求：**R01；问题 A01、A05。

### 建设内容

从一款存在预览/生产混用风险的游戏切入，让维护者生成发布计划，校验服务与环境映射，获得隔离预览，并看清构建、上传、切流和验收的不同状态。先修两处已知危险入口，再复核其他入口，不仅修名称。

### 验收标准

- [x] 两个已知危险入口不再允许预览操作落到生产服务（配置与本地回归通过；S1.3 另完成蓝色星原云端验收，异环仍未部署 staging）。
- [x] 环境或服务名缺失、冲突、未知时发布前失败，不默认回退生产（受控 CLI 范围）。
- [ ] 生产页面不会携带预览禁索引策略，预览不会进入生产 sitemap。
- [ ] 计划显示目标、候选版本、前一版本、预期副作用和审批范围。
- [ ] 上传成功但未切流显示 uploaded/待推广，而不是已上线。
- [x] 蓝色星原授权隔离预览验证后，六个生产服务版本与生产路由保持不变；不扩展为其他服务的云端验收。
- [ ] 生产推广和回滚分别获得相应授权后才执行。

**演示：**故意把预览目标设为生产时被拒绝；合法预览显示其环境和版本，生产不变。

**回退：**停用新入口、保留受控旧生产路径；不恢复已知危险预览别名。

## S2：单游戏数据与 SEO 一致性闭环

**用户故事：**U02、U03。

**关联需求：**R02、R03；问题 A02、A03、A04、A10。

### 建设内容

对选定游戏确认权威内容版本，形成源内容到公开数据、页面、canonical、语言与 sitemap 的一条生成链。通过影子清单对比旧输出，修复一个可复现索引冲突，再扩展同一契约。

### 验收标准

- [ ] 6 对已发现漂移均完成归因和处理决策；不根据新旧文件时间自动选“正确值”。
- [ ] 试点源和所有已识别消费者使用同一内容版本，漂移阻断关联发布。
- [ ] 根 sitemap 正确使用索引结构，主站与游戏子图所有权不冲突。
- [ ] 异环被主动保护的日文页不再由根图重新提交；原神缺译页采用明确阅读/索引政策。
- [ ] 新旧 URL 集合有差分说明，遗漏、增加和取消索引均可解释。
- [ ] 预览核验真实正文、canonical、robots、hreflang、XML 内容类型和资源，不只测 200。
- [ ] 首页重复语言路径及 post-test 展示通过回归；通用元数据策略覆盖基础页面。
- [ ] 对于取消索引/合并页面，不批量删除正文或把所有 URL 跳到首页。

**演示：**同一份内容变更同时出现在预览页面和公开数据，sitemap 只包含真实可索引语言。

**回退：**回退至上一完整内容与清单组合，保留修复前后映射；不只回退其中一个派生物。

## S3：一条官方公告驱动的运营闭环

**用户故事：**U03、U04。

**关联需求：**R04、R09；问题 A06、A11。

### 建设内容

复用现有审核能力，为下一款实际高频游戏加入最小适配。处理一条官方来源，从区服/日期核验到差异判断、修订、预览、发布与线上验收；同时覆盖无需更新和读取失败两条路径。

### 验收标准

- [ ] 内容具有 owner、region、sources、sourceCheckedAt、updatedAt 和 reviewDueAt。
- [ ] 明确区分 announced、已实装和历史归档，不把优化计划写成已上线功能。
- [ ] 无变化只更新核验记录，不伪造文章更新时间或重复创建草案。
- [ ] 读取失败进入待处理状态，不能等同无更新。
- [ ] 审核撤回或输入变更使旧审批失效，不能推广已失效预览。
- [ ] 活动或兑换码到期后不继续作为可领取奖励推荐；未知期限显式说明。
- [ ] 运营能找到逾期内容、负责人和下一步，不需要阅读诊断日志。
- [ ] 获准上线后核对实际内容版本；未获发布授权时停在待发布，状态诚实。

**演示：**同一工作流分别处理“有变化、无变化、读取失败”，三个结论清楚且可追溯。

**回退：**撤回候选或切回上一个已审内容版本；保留来源和审核历史。

## S4：不新增基础设施的新游戏接入

**用户故事：**U02、U05。

**关联需求：**R02、R04、R05。

### 建设内容

使用 GameManifest 和已有通用模板接入一款新游戏，交付约 5–15 个真实有用页面，完成导航、搜索、语言、索引与发布闭环。缺少特殊工具时不伪装为已有完整工具能力。

### 验收标准

- [ ] 标准内容包不新增 Next 应用、Worker 或专属工作流。
- [ ] 新游戏不需要在多个手工游戏名单里重复登记；暂存兼容映射由同一声明生成或对账。
- [ ] 首页、列表、详情、错误页与真实静态资源可访问。
- [ ] 未开放栏目不出现在导航，未翻译语言不自动提交索引。
- [ ] 搜索与站点目录能够找到新内容，并正确标记区服与阶段。
- [ ] 桌面和移动端至少完成一次从平台入口到内容再返回的实际路径。
- [ ] 接入工时、人工修改点和构建成本与现有接入方式可比较。
- [ ] 若标准能力不足，记录例外并停止扩张，不悄悄复制第二套通用模板。

**演示：**增加声明与内容后，新游戏在统一入口出现，完成合法预览与发布状态展示。

**回退：**撤回该游戏候选或回退声明/内容版本，不影响其他游戏；已公开 URL 的下线策略单独处理。

## S5：受影响验证与统一发布记录

**用户故事：**U01、U06、U07。

**关联需求：**R01、R06、R09；问题 A05、A08。

### 建设内容

对一个内容变更与一个共享变更分别计算真实影响范围，执行对应验证集合，把多个服务的状态汇总到一个发布记录。第一版可以是可读清单与脚本，不必新建复杂 Web 后台。

### 验收标准

- [ ] 单游戏内容变更不重建无关游戏，但包含依赖它的跨游戏搜索和摘要验证。
- [ ] 共享代码、锁文件、运行时、未知路径和分类失败触发保守范围。
- [ ] 文档变更不触发生产发布；必需检查不会因路径过滤永久 pending。
- [ ] 同一产物推广的摘要一致；环境特有构建例外明确记录。
- [ ] 多目标发布显示逐服务状态，部分成功不会显示整体成功。
- [ ] 注入中途失败、并发发布和过期审批，能够停止后续动作并提供恢复信息。
- [ ] 记录构建时长、Actions 成本、发布步骤与失败率基线，避免只有理论节省。
- [ ] 保留安全门禁和回滚验证，不能用减少测试制造性能收益。

**演示：**两个不同影响范围的变更生成不同计划；故意制造部分失败时明确显示未完成目标。

**回退：**分类器退回完整验证，发布器停止自动推广；不能以恢复旧状态为由跳过失败核对。

## S6：单游戏内容版本独立发布

**用户故事：**U03、U07。

**关联需求：**R03、R07、R10。

### 建设内容

仅在测量表明内容构建耦合确有成本后，为一款游戏引入不可变内容快照和可回滚的当前版本选择机制。保留服务端正文渲染，验证兼容 schema 与缓存行为。

### 验收标准

- [ ] 内容更新无需重建无关应用，实际耗时与 S5 基线可比较。
- [ ] 正文、公开 JSON、搜索和 PageManifest 使用明确的同一版本或经过验证的兼容组合。
- [ ] 指针更新采用条件更新或等效并发保护，旧发布不能覆盖新发布。
- [ ] 源不可用时按设计使用最后已验证快照或明确失败，不返回空白 200。
- [ ] HTML 和静态资源的旧版本仍在兼容期内可读，跨版本导航不会失效。
- [ ] 私有会话/API 不进入公共缓存。
- [ ] 在测试环境完成内容回滚、缓存一致性和 schema 不兼容拒绝演练。
- [ ] 生产效果必须由获准的真实发布确认，不用本地试验替代。

**演示：**修改一条事实、发布一个内容版本，然后回滚；URL 不变、正文服务端可读、旧资源有效。

**回退：**切回兼容的上一快照；必要时恢复旧读取路径，不删除新旧输入与证据。

## S7：存储治理和有界清理

**用户故事：**U08。

**关联需求：**R08；问题 A09。

### 建设内容

将一个历史实验目录从盘点、引用判断、保护、清理预演、审批到结果核验完整走通；与一次独立备份恢复检查配套，证明缓存与业务数据边界不是只写在文档中。

### 验收标准

- [ ] 清单区分源码、缓存、业务数据、发布证据和未知对象，不按 untracked 判断垃圾。
- [ ] 当前生产、回滚、未结案、活动任务和不完整扫描对象受到保护。
- [ ] 测试覆盖符号链接越界、路径替换、活动状态变化和被引用对象。
- [ ] 预演输出候选摘要，执行前复核；未经批准只能预演。
- [ ] 四个游戏及主站的生成物清理范围一致，业务数据库不进入通用 clean。
- [ ] 统一数据库备份范围，恢复演练使用新目录，不覆盖日常库。
- [ ] 明确隔离移动不释放空间，实际回收在获准删除后测量。
- [ ] 历史图像去重不改变生产 URL、不污染共享输入，逻辑与物理节省分开报告。
- [ ] 记录已删与保留对象、恢复能力和不可逆边界；不把可再生缓存当唯一发布证据。

**演示：**同一清单中，普通缓存可列候选，数据库和被引用发布产物被保护；授权后的单个候选清理可核验。

**回退：**预演无副作用；缓存可重建，归档按已验证路径恢复。无可用恢复手段的持久数据不进入本批删除。

## S8：按实测决定部署分组与容量

**用户故事：**U05、U09。

**关联需求：**R05、R09、R10。

### 建设内容

比较保持当前服务、轻量游戏分组、较少服务配合适当付费容量三种情景。可以得出“不迁移”的结论；只有有明确收益的候选才进行一款或一个小分组的有界迁移。

### 验收标准

- [ ] 当前套餐、平台限制、CI 预算和工时成本有来源；未知项做敏感性分析而非编造数值。
- [ ] 比较包含 gzip、启动/CPU、构建时间、缓存命中、故障范围、发布步骤与回滚时间。
- [ ] 不以多个 Worker gzip 相加预测合并包体，使用实际候选构建测量。
- [ ] 迁移前后 URL、canonical、语言、sitemap、资源与用户操作保持兼容。
- [ ] 先影子核对/受控预览，再获准切换；有明确观察窗口和退回阈值。
- [ ] 失败可回到旧 owner，旧资产和回滚版本在窗口内保留。
- [ ] 观察期后才决定移除旧实现或服务，删除不捆绑在首次切换中。
- [ ] 形成最终 ADR，说明为什么保持、分组或付费，不以 Worker 数量最少作为唯一标准。

**演示：**展示有基线对照的成本与风险决策；若迁移获准，展示相同 URL 在新 owner 下完成验收和回退。

**回退：**恢复旧路由/owner 与兼容版本组合，保留内容修订，不盲目倒退用户数据。

## 4. 批次交付规则

1. 每批有固定基线、需求 ID、允许范围、测试与预算，不直接在混有历史实验的工作区运行通配符全量任务。
2. 本地实现、Git 交付、云预览、生产切换、数据操作和清理分别声明权限，文档不自动授予。
3. 验收输出通过、失败、跳过、未覆盖及证据位置；不把“未运行”描述为通过。
4. CI 与生产失败先判断根因，不重复触发相同流程消耗预算。
5. 每批以一个可观察业务结果结束，避免把大量未接线模块累计为进度。
6. 仅在该批正式接纳后更新原任务总表；不维护第二套互相冲突的“当前已完成”记录。
