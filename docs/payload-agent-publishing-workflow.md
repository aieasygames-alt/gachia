# Payload 代理策划、CMS 入库与本机发布方案

更新：2026-11-04 R36。**该路径已实际运行，修订后的限定V1运行里程碑完成。** 代理规划的NTE标题/导读与独立Genshin阅读路线，均先保存Payload草稿、重读差异并批准，再经本机完整发布链上线；两次公网验收/source-advance及双向共享Main交接通过。不是文档方案、fixture或仅CMS published。证据见[R36](../reports/payload-agent-live-publish-2026-11-04-r36/README.md)。独立密钥继续按用户决定暂缓，不声称全类型CMS或完整灾备完成。

## 1. 操作责任与当前范围

- 用户给出业务方向，也可随时指定游戏/文章；未指定时代理从既有指南选择小批次，先 NTE 后 Genshin。不再要求用户登录后台编写两条验收内容。
- 代理负责选题/修改计划、正文整理、CMS 草稿写入、技术差异检查、批准、导出/构建/精确预览/推广及公网验收。既有常规授权不因增加草稿步骤而变成每篇人工确认。
- 仅限既有 Genshin/NTE guides 的 title/body，zh/en/ja 对应六个导出字段。首批只改中文，一篇一批；事实全面核查和翻译补齐后置，但不编造版本数值、奖励或测试占位文案。
- 新增/删除指南、改 ID/URL/顺序/固定元数据、媒体或其他类型不包含在现有发布能力内；需要独立适配，不得直接改公开 JSON 绕过 CMS。

## 2. 正式内容路径

```text
业务方向 / 代理选择实际优化点
  -> 读取 CMS 正式版本与当前公开内容
  -> 形成单篇、逐字段修改计划
  -> 经本机已认证 Payload API 保存草稿
  -> 重读草稿并核对完整差异、身份、语言和锁
  -> 由现有授权 admin/reviewer 身份批准 published / hold=false
  -> 从 CMS 正式版本导出候选
  -> 本机冻结源码与双 owner 构建
  -> 四版本精确云预览 / 900 秒新鲜门禁
  -> 按序推广 game + Main
  -> 公网验收 / source-advance / 另一游戏共享 Main 交接
```

**Payload 的 published 不等于公网已更新。** CMS 是编辑与批准的入口，本机发布器是执行端；用户所说的“由 CMS 发布到线上”按这条完整路径实现。不是把 CMS 暴露到公网，也不是公众请求实时访问 Mac。Mac 关机时已发布站点仍由 Cloudflare 服务。

## 3. 入库与批准约束

现有 `desktop-content.ts` 仅提供初始 import 与候选 export，没有已交付的通用内容编辑命令。首轮优先复用现有 loopback REST API；若反复操作确有必要，再封装薄的本机适配器，不先建设 Agent 平台、队列或新的审批 UI。

1. 读取目标 stableKey/ID、sourceRecord、正式及草稿版本、目标语言文字、updatedAt 与当前公开 A，形成修改前摘要。保存必要的本机备份，不把账号/session/私有内容放进 Git 报告。
2. 使用现有真实授权身份认证，只请求固定 `127.0.0.1:3100` 的 Payload API。凭证仅私有读取、token 不写日志；不用 SQL 改业务表，不以 `overrideAccess:true` 或 `overrideLock:true` 代替正常权限。
3. 用 `draft=true` 保存目标语言的 title/body；不把其他 locale 的空值覆盖进来。初始未批准内容保持 hold，已批准记录的新草稿不修改其正式 A；不批量清 hold 或撤回历史已上线记录。
4. 重读草稿，核对实际字段与计划一致。写前重读 updatedAt/摘要只能发现漂移，**不等于服务端原子 CAS**；首批按单写者串行操作，遇活跃文档锁或用户并发修改即停止，不覆盖锁。维护锁只互斥本机脚本，不能阻止后台用户编辑。
5. 仅对本篇完成批准，重读 `draft=false` 的正式记录，确认目标文字及 published/hold 状态。批准资格沿用 admin/reviewer，不关闭 R33 的权限约束；不要求用户自己操作批准按钮。
6. 候选必须从正式 CMS 记录导出；完整公开 A→候选 B 差异须符合本次计划，既有公开内容不得丢失。R35 门禁继续拒绝隐式/精确 A→O 重置；不自动重批历史记录、手改 pin、混入草稿或绕过门禁。

技术差异检查不是内容准确度审批。即使不做全量事实核查，仍需确认没有错改文章/语言、泄露草稿、丢失已公开文字或写入未支持字段。CMS 批准后若云发布失败，不能声称网站已同步；保留该批次/阶段与 journal，按既有 partial 对账/显式恢复流程处理，不自动重试云写。
