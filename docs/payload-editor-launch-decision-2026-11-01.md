# Payload 编辑端首发决策

状态：用户进一步指定“Payload 部署本机，以后仅从本机发布”。本机目标环境已完成安装、浏览器与持久性验收；此前 Linux/HTTPS 方案不再是当前前置。本文替代 ADR v2 中编辑端需要先完成 PG/D1 对比的执行顺序，不改写历史证据，也不代表完整公众内容平台已验收。

当前操作入口见 `services/content-cms/deploy/desktop.md`，实际结果见 `reports/payload-local-install-2026-11-01/README.md`。仅本机编辑者访问 loopback，不开放团队远程访问或 Tunnel。GitHub 发布开关已关闭；本机候选到 Cloudflare 的受控发布执行器仍待接通，网站不实时读取本机。

## 决定

1. 首发是独立 Payload 编辑后台，使用 Node + 官方 PostgreSQL adapter + 私有持久媒体卷，单实例启动。暂不继续比较 D1/Worker 编辑服务候选。
2. 先让团队能够登录、录入、修改、保存与恢复版本。内容事实准确度、缺译、命名/标签不统一，以及全量内容/媒体台账不再是后台首发条件。
3. 公众站点保留旧数据源；CMS 的 editorial published 状态不自动激活网站。不在同一批工作中替换所有应用的读取与发布协议。
4. 可以空库起步，不等完整迁移。后续导入保留原文、身份和来源，不隐式修正事实；现有结构/权限校验不删除。
5. 安全权限、真实环境授权、持久化、备份恢复仍是首发条件。媒体权利不是文本准确度：不能借此次优先级调整新增未经授权的公开媒体。

## 为什么这条路线更快

PostgreSQL 已通过真实 Payload migration、编辑权限、版本/锁、事务、HTTP 与数据库故障检查，不再停留在候选机制模拟。单实例私有卷避开首发对象存储适配与多实例一致性工作；旧站点继续独立运行，缩小后台上线的故障影响范围。

代价：首次后台上线不会立即改变公众页面；后续仍需分批导入、选一个公开读取范围完成 CMS-to-site 交接，再扩展更多应用。单实例不能提供多实例高可用；媒体须与数据库联合备份。邮件尚未接入，账号恢复依赖具名管理员与运维流程。

实现、验证结果和目标环境剩余事项见 `reports/payload-editor-launch-2026-11-01/README.md`，操作说明见 `services/content-cms/deploy/README.md`。T05 仅编辑端路径有决定和真实 adapter 证据，T04 的全应用真实内容输出及 T06–T12 不因此关闭。
