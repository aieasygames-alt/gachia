# 账号功能暂时下线与恢复规范

日期：2026-10-23。用户决定当前长期运营方案不以站点登录为前提。本批采取可恢复下线，不销毁历史用户数据，不进行数据库迁移，不修改生产流量。

## 1. 产品边界

| 能力 | 当前候选行为 |
|---|---|
| 公共资料、攻略、搜索、语言切换 | 保留，不要求登录 |
| 无账号的本地工具 | 保留原有行为；本地存储不提供跨设备保证 |
| 登录入口、用户菜单、收藏按钮 | 不展示；浏览器不初始化认证客户端，不轮询会话 |
| Google OAuth、会话查询/退出、历史回调 | 统一返回 404 + `ACCOUNT_FEATURES_DISABLED`，不创建或刷新 Cookie |
| 收藏、角色云存档、地图云进度 | 已实现的 GET/POST/PUT/DELETE 均在认证、限流、解析请求体、访问数据库之前被拦截 |
| 创建共享配装/队伍 | 禁止；依赖此接口的分享按钮不展示 |
| 已有公开共享配装 GET | 保持原有读取能力，不删除记录或改变其既有公开属性 |
| 历史账号、会话、收藏及云端内容 | 保留；不读取真实用户记录，不宣称已注销/清理 |
| IndexNow、公共地图数据和图片代理 | 不因下线登录而关闭，原安全要求保留 |

关闭的是站点账号，不是攻略中的游戏登录说明。不能批量删除游戏内容中出现的“登录”字样。

旧浏览器可能保留此前的 HttpOnly Cookie；本批不通过读取、续期或删除它来建立访问流程。服务器统一拒绝账号入口，旧会话无法绕过门禁。功能下线也不是历史数据物理删除或隐私义务的终结，访问/删除请求仍走隐私政策中的私密邮箱与归属核验流程。

## 2. 实现约束

- `apps/web/site-features.json` 是随源码提交和构建的唯一账号开关，当前 `accountFeatures: false`；不是可被远程环境变量意外打开的开关。
- `lib/site-features.ts` 提供客户端判断及服务端统一响应。接口路由首先调用它；`createAuth` 增加防御性拒绝。
- `lib/auth-client.ts` 在停用时不调用 Better Auth 客户端构造函数，返回稳定匿名会话。既有组件源码及认证策略单元测试保留，便于将来受控恢复。
- `scripts/web-release-policy.mjs` 读取同一 JSON：关闭账号时只免除认证专用 secret，`INDEXNOW_AUTH_TOKEN` 仍必须存在；启用时要求认证密钥和两项 Google OAuth secret。损坏的策略配置直接使发布检查失败。
- 三语言隐私说明区分当前停用、历史留存与本地保存。分析拒绝不再承诺仍可 Google 登录。分析仍默认关闭，仅正式 origin 可以选择启用。
- 主站 `*.workers.dev` 预览使用运行时主机名添加 `X-Robots-Tag: noindex, nofollow`，robots 禁爬；正式域名仍保持原公开索引规则。同一个构建产物可用于 staging 与生产，不以预览构建替代生产构建。

本批未卸载 Better Auth 或删除认证组件、表结构、迁移、secret。立即删依赖会扩大锁文件、数据库兼容和回滚风险；永久清退应在生产稳定及历史数据处置方案确认后单独实施。

## 3. 验收与证据

本地必须包括：三语言入口不展示、没有后台账号请求、带旧 Cookie 的 API 拒绝、损坏请求体仍先被拦截、认证/限流/数据库函数未调用、已有公开分享读取保留、发布 secret 双模式契约、类型检查及真实构建。

```bash
pnpm --filter @gachia/web test
pnpm type-check
pnpm test:release
pnpm --filter @gachia/web exec opennextjs-cloudflare build --config wrangler.jsonc --env ""
node scripts/runtime-rollout-smoke.mjs web
```

本地 Worker 验收故意不绑定 D1/R2、不提供认证密钥、不运行数据库迁移或种子 SQL。保持 HI3 三语言 12 条阅读路由、静态资源、sitemap、404、搜索、客户端导航和桌面/窄屏 × 有 JS/延迟 JS/无 JS 的 18 场景；不能以删除认证测试的方式获得通过，而应改为验证功能确实关闭。

主站云端只允许固定的隔离 staging 验收：

```bash
node scripts/web-staging-acceptance.mjs
```

该入口不接受任意 origin 参数。验证包含对停用接口的有限 POST/PUT/DELETE 请求（无真实身份、损坏请求体），不是全只读抓取；不得换成生产域名运行。浏览器阻止跨域资源，限制请求总量，非压力测试。测试不包含真实 OAuth、真实用户数据及云地图第三方服务可用性。

## 4. 恢复登录不是简单翻开关

1. 新建独立开发切片，重新核准登录需求、数据保留及删除责任；确认继续使用现有表还是迁移，迁移需单独审批与备份。
2. 核验认证依赖安全与运行时兼容，检查历史会话；必要时通过已批准的密钥轮换/会话失效方案阻止旧会话恢复。不能让本次关闭期间的旧 Cookie 自动取得恢复后的权限。
3. 配置 staging 专用 OAuth 客户端、正确回调、足够强度的认证密钥；不复制生产 OAuth 密钥来代替隔离验收。
4. 修改已提交策略并重新构建，同步 UI、隐私披露及 CI 验收。现有“账号关闭”测试应在新切片替换为完整的启用/停用矩阵，不能直接跳过。
5. 验证真实账号登录/退出、Cookie、CSRF、可信源/IP、限流、私有数据隔离、云同步与拒绝路径。单元测试和 secret 名称存在均不代替真实 OAuth 验收。
6. 完成独立 staging、回滚与生产发布前复核后再申请推广。保留本次无账号版本作为可识别的回退候选，不能回到未核验的旧运行时来恢复登录。

## 5. 长期运营建议

优先服务多游戏内容质量、统一发布入口、新游戏模板和本地工具，不为登录增加新的 Worker、数据库或运维链路。未来只有在跨设备进度、用户投稿等需求有明确收益、维护责任和隐私处理闭环时，再恢复账号系统。下线登录会减少功能维护面，但本批不宣称已经合并 Worker、释放磁盘或完成全站上线许可。
