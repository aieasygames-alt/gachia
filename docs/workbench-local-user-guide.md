## 启动与停止

在终端进入项目目录，依赖已经准备好的情况下运行：

```sh
cd /Users/robert/Documents/gachia
pnpm --filter @gachia/admin dev
```

需要Node >=22.18。本说明不要求重新安装依赖。如果提示缺依赖，先诊断，不自行安装或改锁文件。

打开终端打印的本地地址，默认127.0.0.1:4317。地址带一次启动的访问令牌，勿发给他人、勿录入报告或提交。页面接收令牌后会移除地址中的片段，保存在当前标签页sessionStorage。重启后旧令牌失效，请打开新打印的地址。不要绑定公网或转发端口。

停止：在启动终端按Control+C，等待进程退出。若启动了明确批准的应用预览，先在工作台确认其停止状态；关闭浏览器标签不等于服务停止。若端口占用，不直接杀未知进程，可先查看：

```sh
lsof -nP -iTCP:4317 -sTCP:LISTEN
```

本次开发验收已关闭测试服务，没有为你启动日常数据库。

## 日常操作顺序

### 首次使用前检查

确认 Node >=22.18、现有依赖可用、4317 端口没有未知服务占用，并了解本次准备打开的数据
目录是否为旧库。不要发送启动URL或token。已有日常数据应先停服务并备份；备份说明见下文。
如果不确定旧库版本，先停止，不通过启动尝试来诊断。核心验收使用临时库，不是你的日常库。

### 预览选择

“数据预览”不执行 Next；“应用预览”执行已接受草案的真实代码，仍是非沙箱模式。
应用预览必须先审核草案，再在独立工作区准备依赖；依赖准备不是界面自动完成的步骤。
缺依赖或发现 .env/外部依赖链接时保持阻断，不通过复制凭据或绕过检查解决。

### 操作步骤

1. **保存证据**：导入来源链接、摘录、服务器与时间等信息。来源正文不是可信脚本，不导入凭据或个人数据。官方采集为显式手动、有界请求，不是后台定时任务。
2. **核验事实**：逐项检查出处和适用范围。选择人工或代理身份，写核验理由；代理需注明授权依据。身份属于自报记录，不是身份认证。证据不足保持待核验，不因“官方来源”自动通过。
3. **生成任务与修订**：选取已确认事实，查看精确输入及差异；内容、审核或代码基线变化可能使原修订失效。导出的JSON也可能过期，不能当长期有效批准。
4. **准备草案与审核**：创建工作区会写独立Git worktree元数据，需理解并明确使用该功能；不会复制全部脏工作树、安装依赖或自动发布。查看三语、公共镜像、实际差异与审核状态后再接受。
5. **查看预览**：固定数据预览与执行Next代码的应用预览不同。前者不等于真实页面通过；后者是非沙箱代码执行，必须先固定对象、依赖与执行范围。不要为消除“未就绪”而绕过门禁。
6. **查看诊断与历史**：质量覆盖、容量、恢复覆盖和发布计划均为只读诊断。零问题不等于全字段通过；容量候选不授权删除；配置一致不等于当前产物或线上状态通过。

审核后的字段变化会使相关审核/预览过期，这是保护机制。应重新核对并生成新对象，不手工修改数据库来恢复“通过”。

## 数据、备份与异常

数据默认位于项目根目录`.gachia-workbench`，包括`workbench.sqlite`及可能存在的WAL/SHM、迁移备份、工作区和证据。当前schema v13。启动旧库可能进行迁移并先备份；因此不要用启动日常服务来“只读检查”未知数据库。新于应用支持的schema会拒绝，不应改版本号强行打开。

备份前停止服务与预览，确认写入进程结束，然后将整个数据目录复制到一个新的私有位置；若sidecar存在一并保留。不要用旧主库拼接新WAL。普通复制不等于完整灾备验证或跨数据库/工作区原子快照。这里不提供覆盖恢复/删除指令。

出现异常时：保留原文件与错误，先刷新核对保存状态；未知或待对账记录不要立即重复执行。连接故障阻断、审核过期和预览待对账不能靠清库解决。需要恢复时先在新目录验证，勿覆盖日常库。令牌过期则重开本次启动URL。
