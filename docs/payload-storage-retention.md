# Payload 本机磁盘预算与保留策略

更新：2026-11-05 R37。适用仅此Mac的CMS/发布器，**当前只有只读盘点和操作规则，没有自动清理命令**。证据见[R37](../reports/payload-postlaunch-operations-2026-11-05-r37/README.md)，备份见[恢复手册](payload-offsite-recovery.md)。

## 当前基线

R37只读盘点发布根目录约39.15GiB、30个一级目录，解析2931份JSON/JSONL得到87条根级路径引用，无解析失败。数据根约4.32GiB，异地备份本机工作目录小于1GiB；精确时点和分项以本机`storage-final.json`为准。独立目录的du统计可能重复计算共享hardlink，不把各根目录数字相加当唯一物理占用。

该图只是根级引用，排除源码/build/依赖目录，不是完整pin可达性或可安全GC证明。未出现于图中的目录也不能推定无用。本轮零文件删除、零字节回收；不将磁盘空闲增长归因于本轮清理。

## 操作预算

- 可用空间低于10GiB时预警，不再安排无关重构建或复制大制品。
- 低于8GiB时停止开始新的双owner构建，先做审阅后的空间处置；这是手册规则，尚未安装自动磁盘门禁。
- 即使高于阈值，也要按拟执行构建/恢复的临时占用留余量。阈值不是容量充足或构建成功保证。
- 新内容仍先写CMS、冷备、再完整发布；不靠跳过兼容恢复制品或删除历史证据来降低空间要求。

## 必须保留

- 当前应用和已保留的回退应用/工具，698应用文件与28工具的完整性清单。
- 本机冷备、R2下载/认证回执及对应同机私有key；C05b暂缓不等于可以删key。
- R29及之后已封存报告、索引和其固定文件，不能压缩重写、移动后改pin或覆盖日志。
- 当前与历史source-catalog、source-rebind、发布/兼容恢复run及其父来源。node_modules内某些Wrangler/CLI文件也被pin，不默认视为可删缓存。
- 停止/partial/上传intent/推广/恢复journal及依赖；失败目录不是垃圾，仍用于对账和禁止重放。

## 后续清理的前提

先建立完整的pin感知可达性清单，确认活动云UUID、所有当前game/Main来源、恢复目标及封存引用，再提出精确目录级删除计划。对每个候选说明为何不影响来源选择、下一次发布、兼容恢复、历史审计和禁止重放。未完成这一步时默认全部保护，不按“旧于N天”或“未找到字符串引用”删除。

没有启用定时任务、自动GC、R2生命周期删除或配额告警。后续若引入清理器，必须先交付拒绝活动/未知/部分失败/外部引用的dry-run与隔离测试，不能把本轮只读盘点当清理器已完成。
