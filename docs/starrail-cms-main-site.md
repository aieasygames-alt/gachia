## 日常更新

1. 启动本机 Payload，进入「游戏更新」，编辑对应条目。首次使用创建自己的管理员。
2. 保存草稿用于核对；准备公开时点击 Publish。草稿不会进入公开导出。
3. 在 `tools/payload-cms` 执行 `npm run publish:starrail`。使用 Node 24.22.3；没有对应系统 Node 时执行 `npx --yes --package=node@24.22.3 -- npm run publish:starrail`。
4. 命令返回 `ok: true` 和新 `revision` 后，刷新 `https://gachia.com/zh/starrail/version` 及对应攻略URL；阿哈还需查看独立角色页、角色目录与计算器，装备还需查看详情与光锥/遗器目录。这一步无需构建或部署 Worker。

本机已经配置好的编辑与同步目录是原工作区，日常执行：

```sh
cd /Users/robert/Documents/gachia/tools/payload-cms
npx --yes --package=node@24.22.3 -- npm run publish:starrail
```

CMS 未运行时，先在该目录的另一个终端执行 `npx --yes --package=node@24.22.3 -- npm run start`。已有生产构建可直接启动，不需要重新导入数据。

后台 Publish 与同步主站是两个步骤。**本批没有添加后台自动云发布 hook。** 同步命令从匿名可读的 Payload 正式视图导出全体记录，验证后一次性替换云端副本，并从公开接口读回 revision。失败时会报错，修复连接后重新执行；不把本机保存成功当作公网更新成功。

阿哈日常数值维护使用 `aha-character-data` 条目的「角色倍率与材料数据」字段，保留完整五项技能、六次晋阶和十三个节点；角色详情和材料总量会从同一份数据更新，无需手改第二份合计。来源和培养/星魂等级范围须同时核对。原两条叙述性阿哈公告保留为历史核验记录，若事实有修订也应检查其表述。

装备日常维护选择「光锥与遗器」类型，编辑上述17个稳定标识对应的记录；事实数组每项首行为小节标题、其余行按段显示。不要移除触发条件、叠加限制、数值来源或单源边界。此处是显示资料，不自动参与角色材料/伤害计算；修改材料合计时仍需逐项复算。

材料日常维护选择「已核验材料」类型，编辑上述34个稳定标识对应的记录；同步后核对材料详情、材料目录及相关光锥的获取途径入口。材料身份、来源、条件与用量示例在事实数组中维护，合成/置换与商店库存需独立核验；修改示例数量不会自动更改光锥晋阶表或角色计算器，仍需核对原始用量。现有关系由审定注册表控制，新增材料标识或关系需先部署兼容读端，现有正文与数值修订不需部署。

活动日历日常维护选择对应活动记录（当前总览、周期挑战、位面分裂、成名之路、补偿邮件、货币战争、无名勋礼共7条），在「国服结构化活动日历」编辑对应项，并同步核对facts、summary、boundary与sources。`at.value`填写无时区的`YYYY-MM-DDTHH:mm`公告时刻；`after-update`填写date/version；`version-end`填写version；`not-announced`不填推测时间。发布、同步后检查活动页的起止、参与条件、来源及正文锚点，不能把国服公告的无时区时刻改写为自动倒计时。跨记录移动日历项时移除原项，ID不能重复；收信期限必须在标题与说明中明确其含义。

取消发布或删除记录后同样执行同步命令。完整空列表代表主动撤回，页面不会因此恢复内置旧快照。英文和日文按语言隔离，首批没有翻译内容。所有条目保留各自来源核验日期，不因同步刷新核验日。
