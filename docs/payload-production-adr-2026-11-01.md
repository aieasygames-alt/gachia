- 本地 SQLite 有角色/事务/锁/合并/冷备测试；写队列为单进程，有界排队，不支持分布式并发写。
- 账本覆盖 16 scope、116 来源、3,440 候选、106 个 scope/type 组合；2,050 候选仅身份映射，34 个具名区块。730 个本地媒体文件未获得本账本认可的权利回执，139 个页面/layout 文件的内联事实待审。
- R6 双 owner 合成 HTTP 的 CMS 离线行为是拒绝输出，不是公众读侧可用性方案。
- 新本地实验保存两个不可变 release，重新打开文件读取器后仍可读取旧版，覆盖同一 key 被拒，cache identity 随版本变化；过程中不调用 CMS、数据库或网络。仅证明本机文件制品可脱离 CMS 读取，不证明 R2/Worker/灾备。
- 实际安装探针仅发现 SQLite adapter；D1/PostgreSQL/R2 adapter 未安装。不得伪称已有生产适配器对比基准、吞吐、价格或 SLA。

## D1：CMS 托管与编辑数据库

| 方案 | 价值假设 | 必须实测的风险 | 当前建议 |
|---|---|---|---|
| Workers + D1 + 独立 R2 | 沿用 Cloudflare 运维；边缘集成可能简化 | Payload 固定版本适配器、事务回滚、并发锁/抢占、schema migration、包体、图片处理、队列和数据限制 | 保留候选，不用 SQLite 测试替代 |
| Node 托管 + PostgreSQL + 独立对象存储 | 通常更接近完整编辑服务的进程/数据库模型；可将图片处理与后台任务拆开 | 实际 Payload PG 迁移、连接池、并发冲突、队列抢占、备份恢复、托管成本与运维责任 | **优先作为生产基准验证路线**，不是已选择供应商 |
| Node + 当前本地 SQLite | 已有可重现测试，适合开发 | 单进程写、push schema、可丢弃库，不满足现有多进程目标 | 仅实验，不作为默认生产方案 |

建议调整评估方式：不因已有 Cloudflare 网站而强迫 CMS 运行在同一运行时。
先给 Node/PostgreSQL 与 Workers/D1 相同的失败回滚、并发、恢复任务；若 D1 不能满足关键语义，不能靠削弱测试获得通过。
本批不安装/启动 PG、创建 D1 或连接任何云账户；候选运行时实验后才能形成最终决定。

## D2：编辑与公开读取解耦

推荐职责分离：

1. CMS 编辑库：草稿、来源证据、审核/hold、账号、不可变决定；绝不作为匿名公共 DTO。
2. 发布构建器：读取已批准内容，生成完整依赖闭包、公开白名单 Snapshot 与 ReleaseMap；重新验证权限/来源/权利和 schema capability。
3. 不可变制品存储：按摘要寻址，发布制品与 CMS 私有素材/证据分开；上传成功且读回校验后才允许提交激活请求。
4. 公共读侧：读取已激活 release 的保留制品，不逐请求查询 CMS 编辑库；body/RSC/metadata/search/sitemap/media 共享版本约束。

独立 R2 是制品/媒体存储候选，不复用玩家数据 bucket。当前 filesystem 实验只是传输接口模型，不能直接成为生产路径。
权利、来源指针和撤回策略必须在发布 manifest 中绑定；媒体 bytes/hash 正确但 rights 未验证时发布仍拒绝。

## D3：激活、缓存、保留和撤回

- 激活单独授权：批准凭据绑定 releaseKey、owner capability 集合和有效期限；审核者身份不自动取得云部署权限。
- 完整性优先：所有引用制品及 owner 能力读回验证后，以比较并交换的方式更新 active pointer；并发失败需明确冲突，不覆盖他人激活。
- 多 Worker 不承诺原子切换：记录 desired/observed release、各 owner 的确认与失败，定义传播窗口和重试/回退条件。
- 每次请求固定 release；缓存身份至少包含 releaseKey、owner、规范路径、语言/渲染器版本。缺资格的页面不可由旧缓存绕过。
- 保留 active、可回退 predecessor 和仍处传播/在途请求窗口内的版本；GC 先计算引用闭包，再延迟删除。保留数量/时间和 SLO **未定**，需容量与风险预算，不填虚构数值。
- CMS 离线：公开读侧继续读已激活有效版本；制品存储也不可用时如何服务本地缓存由 SLO 决策，不能任意回退到旧源码。
- 紧急撤回不能被长期缓存/保留绕过：单独的撤回策略与失效传播必须在生产前验证。过期、法律撤回和普通回退不是同一种操作。
- 内容回退只改合法的 release 指向；数据库恢复和 Worker 回退另有 runbook，不混为一个“回滚”。

本批第四任务仍用原 no-store shadow transport，**不提前实现生产 active pointer、保留 TTL 或激活协调器**。文件保留实验与实际应用故障拒绝两种证据分别记录。

## 安全与运维门禁

- CMS 认证独立、无公共首用户注册窗口；角色分权、会话/限流、CSRF/媒体访问、日志脱敏、密钥轮换分别验收。
- Payload Local API 的特权调用需核对受控入口；生产审批不能依赖客户端标志或一个 published 字段。
- 制品读者不持有编辑库写凭据；抓取、翻译、审核、制品生成、激活与 GC 使用不同权限。
- 调度、入队、执行分离；有界重试、幂等、死信/告警、任务取消、重复执行和备份恢复是后续必验项。
- 迁移不使用开发态 push schema；建立版本迁移、失败恢复和数据库/媒体/证据/制品联合恢复演练。
- 之前 deepmerge low 风险未在本批重扫或豁免；不能以此 ADR 当安全批准。

## 成本模型（没有报价承诺）

按编辑并发、来源检查频率、候选/修订大小、历史版本数量、媒体字节、制品复用率、读请求/缓存命中、图片处理与任务执行时间估算。
比较 CMS 计算 + DB 存储/请求/备份 + 对象存储/请求/流量 + 调度/日志 + 运维人力。
当前账本的静态大小不是生产访问量；供应商价格、地区、配额及付费套餐要求须在实际选型时读取最新官方资料。
