# 账号数据留存与请求处理

2026-10-16。操作规程候选；不是真实删除执行授权，也不是已验收的自助删除功能。

## 接收与身份核验

使用现有联系页公开的 gachiawiki@gmail.com 私密接收请求。邮箱可达性和人员值守仍需运营核实，不虚构已验证结果。公开 Issue 只处理非个人技术反馈；不得要求用户发送密码、验证码、OAuth code、Cookie、session/access/refresh token。

记录最小工单编号、请求类型、时间与处理状态。以已认证账号或其他经过独立审定的方式核验归属，不以知晓邮箱即可删除。不能核验时暂停处理，不披露账号是否存在。避免将个人信息写入仓库报告。

## 涉及数据与关联

| 数据 | 关联/处理边界 |
|---|---|
| user | 姓名、邮箱、头像及账号ID；关联处理完成后才考虑账号记录 |
| session | user_id、令牌、IP、User-Agent；退出/撤销不代表所有历史副本物理清理 |
| account | user_id、provider标识及可能存在的provider令牌；不读取或打印令牌验证流程 |
| user_favorites / user_characters | user_id；收藏、角色及备注，涉及多游戏用户资料 |
| map_progress | user_id；用户地图进度，不能遗漏独立schema |
| shared_builds | user_id；分享链接、公开内容及缓存需共同评估，不能只删除账号 |
| verification | 无统一user_id外键；需核实框架identifier映射，不按邮箱盲删 |
| rate_limits | 按IP/接口键，不能安全等同某个账号；不删除其他用户计数 |

上述仅为源码模型清单，不是生产表状态证明。外键未普遍配置级联删除，不可直接启用框架自助删除就宣称业务数据同步清理。

## 留存边界

应用会话配置明确7天有效期、1天更新间隔，是访问有效期，不是物理清理期限。验证记录使用其expiresAt；业务记录及备份尚未确定经过验收的统一清理期限。GA/provider后台留存、跨境/地区要求、广告CMP和数据处理约定仍需独立核实。

不要在说明中承诺未实现的自动清理，不以“已过期”证明数据库或备份已无数据。

## 删除执行前门禁

1. 固定代码/数据模型，复核请求归属和范围，得到明确的数据操作授权。
2. 在新建合成数据库验证关联范围、外键、事务失败回滚、幂等、会话撤销及共享内容行为；不复制真实个人数据做演练。
3. 明确生产备份、缓存和第三方副本的处理策略及实际保留期限，避免恢复备份使删除数据重新生效。
4. 只执行经审查的参数化操作，保留不含个人数据/令牌的审计结果；失败停止，不手工追加无界删除。
5. 向请求人私密告知实际完成范围、未完成部分及下一处理方式，不声称第三方数据已同步删除。

当前没有真实删除演练或执行，禁止将本文件当作可直接运行的SQL清理脚本。
